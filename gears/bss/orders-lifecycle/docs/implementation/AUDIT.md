# S2-06 transactional audit and canonical integrity encoding

Status: **implemented, independently gap-fix reviewed and locally verified**. The scope is the audit byte contract, the sealed transactional writer, configured actor classes and audit minimization. Of the public business operations only draft authoring and the draft reads are exposed (S2-09, early S6-01/S6-04, S2-12); submit, amendments and fulfillment stay unavailable. The engine (S2-04) is the only intended production caller. The verification worker and checkpoints are S2-11.

## Delivered

| Area | Implementation |
|---|---|
| Canonical encoding | [domain/audit.rs](../../orders-lifecycle/src/domain/audit.rs) `preimage`. Frozen v1 (D-99) and v2 (D-143) plus v3 (D-201), selected by the stored `hash_version`. NULL-safe `F` framing; 16-byte UUIDs; unsigned big-endian positive sequence/version; signed big-endian microsecond `created_at`; exact UTF-8 text; 32-byte digests. The `force_request_observation` is typed binary framing, not JSON. The encoder destructures the row exhaustively. Unknown versions, evidence a version cannot cover, malformed lengths and sub-microsecond instants are refused. Genesis and the D-100 roll-up genesis/digest are also encoded here. SHA-256 comes from the FIPS `aws-lc-rs` provider |
| Writer row shapes | `AttemptEvidence` builds every value before sealing. It covers: committed create (sequence 1 from genesis, version 1, a fresh draft whose namespace equals its resource tenant); ordinary committed transitions (before/after facts of one locked aggregate, closed caller-text rule per trigger, the D-201 internal token); administrative edits (one entry per changed allowlisted field, `lines/<id>/<field>`); resolved refusals (observed state/version, no sequence or chain, with the D-201 observation for a `second-approver-required` force request); and unresolved refusals (only the validated requested identifier, everything else NULL). `SealedAudit` can only be produced by sealing, and new writers seal v3 |
| Transactional writer | [repo/audit.rs](../../orders-lifecycle/src/infra/storage/repo/audit.rs). `append_committed` allocates `audit_sequence + 1` from the locked aggregate (never a DB sequence or the commercial version). It links genesis or the stored predecessor digest, requires that the entry matches the locked row's frozen namespace, resource tenant, state and version, inserts in the caller's transaction and advances the counter. `append_committed_all` covers administrative edits. `append_resolved_refusal` takes no sequence. `append_unresolved_refusal` does no lookup or lock and runs under the subject-tenant refusal scope. `committed_chain_page` is the verifier read. The raw row insert is visible only inside storage, and `LockedOrder::replace` refuses any `audit_sequence` change, so the counter advances only with a sealed append |
| Verifier | `verify_entry` checks shape, supported version, digest length and recomputed digest. `ChainVerifier` streams one predecessor at a time and checks namespace/order binding, contiguity from 1, genesis/predecessor equality and reconciliation with the aggregate counter. It recognizes v1/v2/v3 in one chain and never resolves identities |
| Actor class (D-115) | `ActorIdentities` comes from the required `service_principals` config plus the maintenance actor. Matching uses `(subject_id, subject_tenant_id)`, and startup fails closed. See the [gear README](../../README.md#configuration-and-lifecycle) |
| Minimization (D-96, keyed by D-204) | Caller text is 1–4096 characters with no control characters. A committed `acknowledge-failed` records only a closed D-136 `failure_reason` value, never `operator-forced-unreconciled` (D-182). The administrative allowlist: `external_reference` is verbatim (bounded, credential-free); `display_label`/`internal_notes` are `hmac-sha256:v1:<key_id>:<hex>` (aws-lc-rs HMAC-SHA256) behind the one replaceable `minimized_text_digest(&AdminTextKey, …)`; the key comes from the required `audit_minimization { key_id, key }` config (secret reference via `#[expand_vars]`, 32–1024 bytes, redacted `Debug`, startup failure when missing, unresolved, short or with a malformed `key_id`). Delegation proof references embedding credentials (compact JOSE, PEM, URL user-info, secret parameters) are refused |

## Boundaries

- **S2-04** calls the writer on every committed and refused path. It maps writer errors to an aborted transaction and settles idempotency with the returned audit identity. The S2-05 settlement composition is demonstrated in a PostgreSQL test. S2-08 adds the outbox.
- **S2-11** runs the rolling verifier and the checkpoint/header/member append under the verifier/checkpoint roles. This package supplies the pure encodings and the chain read only.
- The REST adapter's `api::rest::delegation_proof` already maps a credential-bearing `X-Delegation-Proof-Ref` to `request-invalid` through `validate_proof_reference` (D-202; `authz::tests::malformed_oversized_or_duplicate_proof_headers_are_request_invalid`). **S2-12** mounts it before authorization on every route.
- **Fixture correction (gap review).** The `v{1,2,3}-resolved-refusal` vectors had stored `to_state = NULL`, which contradicts Foundation §3.7 and D-98 and the S2-02 CHECK. The independent Python generator now authors `to_state = from_state`, and only those three digests changed ([CONFORMANCE](CONFORMANCE.md)). `infra::storage::tests::audit::refusal_vectors_store_as_rows_and_verify_against_the_ddl` stores every refusal vector as a row, verifies it, and shows the DDL refuses the old shape. Runtime, DDL and vectors now agree.
- **Keyed minimization (D-204).** The unkeyed interim digest is replaced by a keyed HMAC; values are deterministic per key, differ across keys and key IDs, keep NULL as NULL and keep whitespace/case-only changes distinct (the PostgreSQL `prior_value IS DISTINCT FROM new_value` CHECK admits them). Tests: `domain::audit::tests::keyed_admin_text_minimization_is_deterministic_per_key_and_never_exposes_the_key`, `administrative_edits_write_one_minimized_entry_per_changed_allowlisted_field`, `gear::tests::audit_minimization_key_is_required_redacted_and_validated`, PostgreSQL `infra::storage::tests::audit::sealed_chain_round_trips_through_postgres_and_verifies_from_stored_bytes` (no plaintext in any stored column, no `sha256:` values). No conformance vector changed: the admin-edit vectors cover only verbatim `external_reference`. A keyed pseudonym is not anonymization; Privacy/Legal approval stays open under `cpt-cf-bss-orders-lifecycle-upreq-audit-identity-lifecycle`.
- **Proof reference.** The supplied reference is stored. PDP-reported accepted references are not observable today (D-111).
