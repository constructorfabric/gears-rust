# S2-12 foundation integration milestone: pre-engine throttling, route census, readiness and the live E2E host

Status: **implemented, independently gap-fix reviewed and locally verified** ([implementation report](../../../../../artifacts/orders-lifecycle-s2-20261006/S2-12-implementation.md), [gap review](../../../../../artifacts/orders-lifecycle-s2-20261006/S2-12-gap-review.md)). The gap review (2026-10-07) corrected the edge limiter's key bound (tracked pairs are never refused by the bound, reclamation is rate-limited), moved every mounted route to the toolkit's canonical `Path` extractor, added the per-order fallback and malformed-path seams to the live E2E, and closed the formatting, Clippy and documentation gates the implementation left open.

- **Scope:** [Foundation contract §3.7](../DESIGN.md#contract-01-3-7) pre-engine request limiter ([01 §3.4 item 6](../features/01-foundation.md), D-185, Q-26 fallback), [08 §3.3](../DESIGN.md#contract-08-3-3) route exposure and the [08 §4.5 census](../features/08-read-and-authz.md), [§3.8 health reporting](../DESIGN.md#contract-01-3-8) (readiness, not liveness), and the live HTTP/PostgreSQL E2E host of the draft milestone ([E2E acceptance](../../../../../artifacts/orders-lifecycle-s2-20261006/E2E_ACCEPTANCE.md)).
- **Decisions:** [D-211](../DECISIONS.md#d-211--the-foundation-integration-milestone-pre-engine-throttling-bindings-the-delivered-route-census-real-readiness-and-the-live-e2e-host-s2-12).
- **Package text:** [02-foundation-and-capture.md § S2-12](02-foundation-and-capture.md#s2-12--close-the-foundation-integration-milestone).

The package closes the S2 integration milestone: authorized draft capture (S2-09) and draft inspection (early S6-01/S6-04) are operable over TCP against the real gateway, AuthN, the rules PDP with the real `PolicyEnforcer`, PostgreSQL under the restricted runtime login, the sealed audit writer and the bound Event Broker producer. Draft cancel, Preview, submit, amendments, holds and the Workflow seams stay **unavailable**: their catalog contracts are registered, their routes are not mounted, and the local SDK answers `unavailable`. Successful production submit is not claimed; the Stage 3 real-provider gates remain.

## Limitations and hand-offs

1. **Per replica.** Both the gateway zones (throttling ADR-0001 open) and the edge limiter hold state per process; a deployment of N replicas admits up to N× the configured budgets.
2. **Fallback, not the gateway key.** The per-(caller, order) limiter is the documented Q-26 fallback; Orders removes it when `cpt-cf-bss-orders-lifecycle-upreq-gateway-path-param-throttle-key` lands ([UPSTREAM_REQS §2.12](../UPSTREAM_REQS.md#212-api-gateway)). Its key bound is approximate under concurrency (two simultaneous new pairs may both take the last slot), like the gateway's.
3. **Workflow zone unused until S5-08.** `rl_orders_workflow_write` is configured and pinned; no workflow operation is mounted, so no live traffic exercises it.
4. **Deployment gates unchanged.** Production provider and policy provisioning (`upreq-pdp-policy-integration`), broker partition equality (D-205), identity provisioning of the runtime and worker logins, and the gateway zone configuration are deployment conditions; the E2E host provisions test identities only.
5. **Readiness probe cost.** Each `/readyz` call performs one scoped store read (the platform date-policy default) bounded by 2 s.
6. **E2E host override.** The live suite runs the per-order limiter at 10/min (host `config.yaml`), below the §3.7 baseline, so the fallback and the gateway zone are distinguishable over TCP; production keeps the baseline.
7. **Draft cancel** is Stage 5 and not mounted; the suite asserts its path is unrouted.
