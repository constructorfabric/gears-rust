# S2-02 storage delivery

Status: **implemented, independently gap-fix reviewed and locally verified**. Scope is the Orders database schema and internal secure repositories. Of the public business operations only draft authoring and the draft reads are exposed (S2-09, early S6-01/S6-04, S2-12); submit, amendments and fulfillment stay unavailable, and this does not mark production readiness complete.

The runtime is the sole owner of 24 `bss_orders__` tables. Its eight ordered migrations follow the Event Broker registration and ToolKit outbox migrations supplied by their owners. The [generated inventory](../../orders-lifecycle/src/infra/storage/migrations/schema-inventory.json) records 312 columns with types/nullability, all keys/checks/indexes, content owners/scopes, role grants and mutation guards. The [migrations](../../orders-lifecycle/src/infra/storage/migrations/mod.rs), [entities](../../orders-lifecycle/src/infra/storage/entity/mod.rs) and [secure repositories](../../orders-lifecycle/src/infra/storage/repo/mod.rs) are internal runtime APIs.

Current-parent scope and complete proposed inserts are enforced through SecureORM. Locked contributions accept the same `DbTx`/`SecureTx`, sparse versions retain explicit predecessors, removed draft IDs remain reserved, native intervals preserve calendar semantics and D-193 authored intent, and D-201 audit v3/grant linkage preserves frozen v1/v2 readability. Append-only evidence, permitted operational updates, bounded counters, retention windows and separate writer/checkpoint/policy roles are enforced in PostgreSQL. No Orders evidence FK cascades deletion.

Validation used Rust `+1.98.1`, actual PostgreSQL through the established test-container helper, Clippy with warnings denied, formatting, architecture lint, schema inventory and source-coverage/document checks. The runtime/SDK suite passed 63 tests with none ignored; the final focused storage run passed all 24 PostgreSQL tests. The role/outbox test exercises the owner's real transactional enqueue under the restricted runtime role and verifies rollback; it is not a broker-publication or production-provider conformance claim.

The independent [gap review](../../../../../artifacts/orders-lifecycle-s2-20261006/S2-02-gap-review.md) closed six findings: dispatch grants now form one linear chain from a single first-spawn grant; audit, registry, diagnostic-run and checkpoint writers accept only the caller's transaction; the resolved audit read is an explicit `(created_at, audit_id)` keyset page (maximum 200) instead of a silently truncated list; claim release uses database time; and the manifest test compares constraint/index definitions and requires exact role privileges with no undeclared objects. The storage suite now has 27 PostgreSQL tests.

The [implementation report](../../../../../artifacts/orders-lifecycle-s2-20261006/S2-02-implementation.md) contains the original requirement/source-to-path-to-test mapping, every table, compatibility choices and limitations; the gap review supersedes its test counts. The next step is S2-03. Engine algorithms, audit hashing, producer lifecycle, public draft routes, maintenance workers and deployment identity binding remain in their named packages.
