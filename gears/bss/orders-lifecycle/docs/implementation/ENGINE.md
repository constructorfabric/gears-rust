# S2-04 declarative transition engine

Status: **implemented, independently gap-fix reviewed and locally verified**. The scope is the [complete algorithm](../features/01-foundation.md#contract-01-3-6), the [state table](../features/01-foundation.md#contract-01-order-state-machine) and the [engine contract](../DESIGN.md#contract-01-4-1). The engine composes the delivered S2-03 PEP, S2-05 registry gate and durable executions, S2-06 sealed v3 audit writer, S2-07 step-17 claims and the S2-08 managed producer; it does not reimplement them. Of the public business operations only draft authoring (create and the `draft-mutate` row, S2-09) and the draft reads are exposed (S2-12 mounts them); every other row is unreachable until its owning package supplies its slice predicates, contributions and event detail.

## Ordering and placement

Existing-order attempt: authorization (point prefetch + PDP; denial audits unresolved evidence and settles nothing) → advisory probe (authorized replay re-resolves no input and rechecks disclosure) → coherent draft snapshot under the aggregate lock released before slice calls → slice preparation → one transaction: aggregate lock and fact recheck (`Stale` → `version-conflict`/`authorization-context-changed`, `AccessLost` → non-disclosing `order-not-found`, neither settles) → registry gate (aggregate before registry) → decision → subflow/contribution checks → step 17 claims → step 18 version → step 19 child documents → steps 18.2–21 aggregate write → step 22 sealed audit (per changed field for row 3) → step 24 the row's one event from the committed post-state → step 25 settlement → commit. Nothing takes a claim after step 17, and a collision is refused before any version or document write.

## Gap review (2026-10-06)

The independent review fixed: the single-writer boundary (event details no longer receive the locked aggregate; the gate covers aggregate-handle acquisition and raw writes); row 3's change guard and per-field audit now use the values stored at the engine's locked read (`GuardSubject::administrative`, `contributions::reconcile_administrative`), so a concurrent edit cannot falsify an audited prior value or turn a checked change into a no-op (04 §3.6 step 2); the D-179 holder disclosure uses the caller's untargeted read scope, and a read denial no longer refuses a submit/amendment without audit; draft-line removal and line-fulfillment replacement reach slices through `ChildDocuments`; `transition` refuses `create` (D-105). Added PG tests: `administrative_edits_compare_with_the_locked_values`, `a_collision_never_names_the_holder_to_a_caller_without_read_authority`, `draft_edits_add_and_remove_lines_through_the_bounded_handle`; the fault test now also covers a versioning row with a claim at all 8 boundaries and asserts no later boundary runs; the refusal sweep asserts v3, tenant equality, the settled-refusal audit link and no claim/grant.

## S2-FINAL cleanup (2026-10-07)

The coordinator's design-traceability review found one latent defect: `prepare_durable` (the D-188/D-198 preparation subflows) mapped `AuthorizedLock::AccessLost` at its lock-and-recheck to the same conflict as stale facts, which settled as `authorization-context-changed` and so disclosed the target's existence, while the ordinary paths (`lock`, `snapshot`) answer the non-disclosing `order-not-found` (D-114, D-141). The subflow now carries the recheck reason: stale facts map through `StaleAuthorization::reason` (`version-conflict`/`authorization-context-changed`, as the ordinary paths), lost access is `order-not-found`; both stay unresolved evidence and settle nothing. Added PG tests: `durable_preparation_maps_stale_facts_to_conflict_and_lost_access_to_not_found` (a concurrent writer holds the aggregate lock, changes the payer or the resource tenant and commits while the authorized preparation blocks; commercial subflow both arms, receiver-control subflow stale arm; no candidate, control, registry row or disclosing evidence; the same key runs fresh) and `an_outbox_insert_failure_rolls_back_the_business_effect_and_audit` (INSERT revoked on `toolkit_outbox_body` for the runtime role: an eventful row's state change, dwell clock, committed audit and key claim all roll back as a confirmed `Internal` outcome, nothing is enqueued, and the same key commits once the grant returns). The engine suite is 18 PostgreSQL tests.

## Boundaries

- **Slice logic is not here.** Every guard predicate, document contribution and event detail belongs to its owning package (S2-09/10, S3-12, S4-01/05/08/10, S5-03/04/10/11/13/15). Until a package delivers its operation, that row is unreachable; its declaration and binding contract are fixed here.
- **Stage 3 diagnostics.** The engine stores a supplied assessment snapshot with the settled response and marks gate-composite refusals; persisting `orders_gate_outcome` rows (identical run metadata, predicate-9 replacement) is the S3 assessment owner's.
- **D-198 grants.** The engine plans the generation increment, requires a grant contribution and supplies its audit/execution links; the grant's roster verification and the receiver-barrier finalization guards are S5-02/S5-04/S5-09. Row 12 and post-spawn resume are unavailable without that contribution; post-spawn hold/cancel/failure are unavailable without a D-198 control.
- **D-201 internal rebuild** registers separately (S5-02); it is not a public row.
