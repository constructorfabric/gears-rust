# 412 - sequence violation

The only producer-protocol error that escapes to callers. A chained-mode publish that neither advances the chain nor resends its head (`meta.sequence == last_sequence` is a duplicate) maps to canonical `FailedPrecondition` and is rejected with status `412` - a `TransportOverride` over the category's own status, per the Hard-Error Catalog in [DESIGN.md](../../docs/DESIGN.md) - carrying the broker's current value for resync.

## Request

```http
POST /v1/events HTTP/1.1
Host: broker.example.com
Authorization: Bearer <tenant-token>
Content-Type: application/json

{
  "id": "c0000000-0000-0000-0000-000000000099",
  "type": "gts.cf.core.events.event.v1~acme.orders.created.v1~",
  "tenant_id": "<tenant-uuid>",
  "source": "order-service",
  "subject": "order-chain",
  "subject_type": "gts.cf.core.events.subject.v1~acme.order.v1~",
  "occurred_at": "2026-05-29T10:08:00Z",
  "data": { "order_id": "order-chain", "total_cents": 700 },
  "meta": { "version": 1, "producer_id": "{producer_id}", "previous": 3, "sequence": 4 }
}
```

## Expected response

- `412 Precondition Failed` (`PD`)
- The broker's current `last_sequence` is in `context.violations[0].description` for resync. It is not repeated in `detail`, which names the precondition only: an error must carry no part of the submitted value, and `meta.previous` was caller-supplied.

```json
{
  "type": "gts://gts.cf.core.errors.err.v1~cf.core.err.failed_precondition.v1~",
  "title": "Failed Precondition",
  "status": 412,
  "detail": "Operation precondition not met",
  "instance": "/v1/events",
  "trace_id": "<request-trace-id>",
  "context": {
    "resource_type": "gts.cf.core.events.topic.v1~",
    "resource_name": "gts.cf.core.events.topic.v1~acme.orders.v1",
    "violations": [
      {
        "type": "sequence_mismatch",
        "subject": "(producer)",
        "description": "index=0 producer_id={producer_id} topic=gts.cf.core.events.topic.v1~acme.orders.v1 last_sequence=7"
      }
    ]
  }
}
```

## Notes

Endpoint-specific instance: [flows/negative-1.5](../producer/flows/1.05-negative-chained-sequence-violation.md). For `:batch`, a violation on any event rejects the whole batch atomically.
