# List event types

Returns a paged list of the event types registered in `types_registry` that the caller may read: it may consume the type's topic, or publish the type, in its own tenant; a type it may not read is left out, with no error. Producers use this to discover which event types are available on a given topic; consumers use it to understand the data schemas they'll receive.

## Request

```http
GET /v1/event-types?$filter=topic eq 'gts.cf.core.events.topic.v1~acme.orders.v1'&limit=20 HTTP/1.1
Host: broker.example.com
Authorization: Bearer <tenant-token>
```

## Expected response

- `200 OK`
- Each item is a DTO projected from that event type's registered type schema: `id` is the schema's own type identifier, `topic`, `allowed_subject_types` and `partition_key` (the pointer that decides an event's partition) are its resolved trait values, and `data_schema` is the payload contract composed from the `data` narrowings along the derivation chain.

## Side effects

- Read-only. No state changes.
