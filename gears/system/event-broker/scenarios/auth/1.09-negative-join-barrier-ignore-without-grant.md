# JOIN across a barrier without the barrier right → 403

An interest with `barrier_mode: ignore` asks to read across a self-managed tenant boundary. Before anything else for that group, the broker asks the policy for `consume_ignore_barrier` on the topic, rooted at the interest's tenant only. A caller without that right is refused `403 TenantIdNotAuthorized`, and the broker asks nothing more for the group: a `consume` grant on the topic does not help.

## Setup

- Tenant tree: `T123` (the caller's tenant) has the self-managed child `B234`.
- The caller, in `T123`, holds `consume` on `gts.cf.core.events.topic.v1~acme.orders.topic.v1` and `consume` on consumer groups, but not `consume_ignore_barrier`.
- Group `{group_id}` exists, created by the caller.

## Request

```http
POST /v1/subscriptions HTTP/1.1
Host: broker.example.com
Authorization: Bearer <T123-token>
Content-Type: application/json

{
  "consumer_group": "{group_id}",
  "client_agent": "worker/1.0.0",
  "interests": [
    {
      "topic": "gts.cf.core.events.topic.v1~acme.orders.topic.v1",
      "subject_tenant": "<B234-uuid>",
      "ownership_filter": "entire_tenant",
      "barrier_mode": "ignore",
      "types": ["gts.cf.core.events.event.v1~acme.orders.created.v1~"]
    }
  ]
}
```

## Expected response

- `403 Permission Denied` (`TenantIdNotAuthorized`)

```json
{
  "type": "gts://gts.cf.core.errors.err.v1~cf.core.err.permission_denied.v1~",
  "title": "Permission Denied",
  "status": 403,
  "detail": "You do not have permission to perform this operation",
  "instance": "/v1/subscriptions",
  "trace_id": "<request-trace-id>",
  "context": {
    "reason": "access denied by policy",
    "resource_type": "gts.cf.core.events.request.v1~"
  }
}
```

## Side effects

- No subscription is created; `GET /v1/subscriptions` for `{group_id}` lists none.
