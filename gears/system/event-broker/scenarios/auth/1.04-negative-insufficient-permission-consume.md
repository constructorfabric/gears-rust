# Principal without a consume grant → 403

JOINing a subscription of an anonymous group asks the policy, after the creator check, for `consume` on the consumer group (the group check: the group family resource `gts.cf.core.events.consumer_group.v1~`, naming the group and its tenant, in that tenant), then for `consume` on the topic, asked once for each group of interests (the same topic, tenant and barrier mode) and naming that group's event types; the answer's scope limits which event types the subscription receives. A principal with no `consume` grant at all is refused by the first of these, the group check: `403 Permission Denied` (`ConsumerGroupNotAuthorized`) at JOIN time - no subscription is created. tr-authz and static-authz pass the group check for the group's creator in its own tenant, so only an action-aware policy shows this refusal. A refusal of the group check alone is [Group check refused](../consumer/subscriptions/1.17-negative-join-consumer-group-not-authorized.md); a refusal of the topic alone is [Unauthorized topic JOIN](../consumer/subscriptions/1.06-negative-join-unauthorized-topic.md).

## Setup

- The policy grants the caller `define` on consumer groups and no `consume` grant.
- The caller created the anonymous group `{group_id}` in its own tenant (`POST /v1/consumer-groups`), so the creator check passes.

## Request

```http
POST /v1/subscriptions HTTP/1.1
Host: broker.example.com
Authorization: Bearer <token-without-consume-grant>
Content-Type: application/json

{
  "consumer_group": "{group_id}",
  "client_agent": "report-runner/1.0.0",
  "session_timeout": "PT30S",
  "interests": [
    {
      "topic": "gts.cf.core.events.topic.v1~acme.orders.v1",
      "subject_tenant": "<tenant-uuid>",
      "ownership_filter": "entire_tenant",
      "types": ["gts.cf.core.events.event.v1~acme.orders.*"]
    }
  ]
}
```

## Expected response

- `403 Permission Denied` (`ConsumerGroupNotAuthorized`)

```json
{
  "type": "gts://gts.cf.core.errors.err.v1~cf.core.err.permission_denied.v1~",
  "title": "Permission Denied",
  "status": 403,
  "detail": "You do not have permission to perform this operation",
  "instance": "/v1/subscriptions",
  "trace_id": "<request-trace-id>",
  "context": {
    "reason": "<PDP deny reason, or \"access denied by policy\">",
    "resource_type": "gts.cf.core.events.consumer_group.v1~"
  }
}
```

## Side effects

- No subscription is created. No group state is modified.
