# Producer registration the tenant check refuses → 403

`POST /v1/producers` stores a producer in the caller's own tenant. After the request body passes its checks (`mode`, `client_agent`), the broker asks the policy for `produce` on the request resource, rooted at the caller's tenant. A refused caller gets `403 Permission Denied` (`TenantIdNotAuthorized`) and no producer is stored. A malformed `client_agent` is still a `400`, answered before the policy is asked.

## Setup

- The deployment authenticates with static tokens. The token `<nil-tenant-token>` is bound to an identity with a fixed subject id and the nil tenant `00000000-0000-0000-0000-000000000000`.
- The policy refuses that caller's tenant check: the shipped policies refuse every request from a nil tenant.

## Request

```http
POST /v1/producers HTTP/1.1
Host: broker.example.com
Authorization: Bearer <nil-tenant-token>
Content-Type: application/json

{
  "mode": "chained",
  "client_agent": "order-service/1.0"
}
```

## Expected response

- `403 Permission Denied` (`TenantIdNotAuthorized`)

```json
{
  "type": "gts://gts.cf.core.errors.err.v1~cf.core.err.permission_denied.v1~",
  "title": "Permission Denied",
  "status": 403,
  "detail": "You do not have permission to perform this operation",
  "instance": "/v1/producers",
  "trace_id": "<request-trace-id>",
  "context": {
    "reason": "access denied by policy",
    "resource_type": "gts.cf.core.events.request.v1~"
  }
}
```

## Side effects

- No producer is stored: no `producer_id` is minted, so there is nothing to publish with or read cursors for.
