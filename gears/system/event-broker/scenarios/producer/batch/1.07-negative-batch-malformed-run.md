# Batch rejected for a run that does not link

Inside a chained run, every event after the first takes the prior event's `sequence` as its `previous` (feature 0001 §5.2, R3). The check runs before any chain state is read, so a run that breaks it is rejected `400 malformed_run`, naming the first offending event, whatever the producer's head is.

## Setup

- Topic `acme.orders.v1` and event type `acme.orders.created.v1` registered.
- Producer `{producer_id}` registered in chained mode, with no event published yet.

## Request

The run is `[0->1, 2->3]`: the second event's `previous` (2) does not link to the first event's `sequence` (1).

```http
POST /v1/events:batch HTTP/1.1
Host: broker.example.com
Authorization: Bearer <tenant-token>
Content-Type: application/json

{
  "events": [
    {
      "id": "e0000000-0000-0000-0000-000000001201",
      "type": "gts.cf.core.events.event.v1~acme.orders.created.v1~",
      "tenant_id": "<tenant-uuid>",
      "source": "order-service",
      "subject": "order-gap",
      "subject_type": "gts.cf.core.events.subject.v1~acme.order.v1",
      "occurred_at": "2026-05-29T10:11:00Z",
      "data": { "order_id": "order-gap", "total_cents": 100 },
      "meta": { "version": 1, "producer_id": "{producer_id}", "previous": 0, "sequence": 1 }
    },
    {
      "id": "e0000000-0000-0000-0000-000000001202",
      "type": "gts.cf.core.events.event.v1~acme.orders.created.v1~",
      "tenant_id": "<tenant-uuid>",
      "source": "order-service",
      "subject": "order-gap",
      "subject_type": "gts.cf.core.events.subject.v1~acme.order.v1",
      "occurred_at": "2026-05-29T10:11:01Z",
      "data": { "order_id": "order-gap", "total_cents": 200 },
      "meta": { "version": 1, "producer_id": "{producer_id}", "previous": 2, "sequence": 3 }
    }
  ]
}
```

## Expected response

- `400 Bad Request` (`PD`)

```json
{
  "type": "gts://gts.cf.core.errors.err.v1~cf.core.err.invalid_argument.v1~",
  "title": "Invalid Argument",
  "status": 400,
  "detail": "Request validation failed",
  "instance": "/v1/events:batch",
  "trace_id": "<request-trace-id>",
  "context": {
    "field_violations": [
      {
        "field": "events[1].meta",
        "description": "does not follow the same producer's event before it in the batch",
        "reason": "malformed_run"
      }
    ],
    "resource_type": "gts.cf.core.events.request.v1~"
  }
}
```

## Side effects

- Nothing is stored, and the producer's head row for the topic stays absent: `GET /v1/producers/{producer_id}/cursors` still lists no topic.
