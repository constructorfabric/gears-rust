# Batch rejected for carrying no events

A `:batch` carries at least one event (feature 0001 §5.2, R1). An empty `events` array is rejected `400 empty_batch`.

## Setup

- Topic `acme.orders.v1` registered.

## Request

```http
POST /v1/events:batch HTTP/1.1
Host: broker.example.com
Authorization: Bearer <tenant-token>
Content-Type: application/json

{
  "events": []
}
```

## Expected response

- `400 Bad Request` (`PD`)

```json
{
  "type": "gts://gts.cf.core.errors.err.v1~cf.core.err.invalid_argument.v1~",
  "title": "Invalid Argument",
  "status": 400,
  "detail": "Request validation failed",
  "instance": "/v1/events:batch",
  "trace_id": "<request-trace-id>",
  "context": {
    "field_violations": [
      {
        "field": "events",
        "description": "a batch carries at least one event",
        "reason": "empty_batch"
      }
    ],
    "resource_type": "gts.cf.core.events.request.v1~"
  }
}
```

## Side effects

- Nothing is stored.
