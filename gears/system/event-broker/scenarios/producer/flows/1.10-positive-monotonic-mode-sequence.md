# Monotonic-mode publish accepts a gap

A producer registered in monotonic mode supplies `meta.producer_id` and `meta.sequence`, and omits `meta.previous`. The broker admits the event when `meta.sequence` is strictly greater than its stored `last_sequence` for `(producer_id, topic, partition)`. The step may be larger than one: gaps are allowed, because a monotonic producer does not claim to know what the broker last saw - only that it never goes backwards.

This is the difference from [chained mode](./1.03-positive-chained-mode-sequence.md), which requires `meta.sequence == last_sequence + 1` and a matching `meta.previous`. Mode is fixed at [registration](./1.02-positive-register-monotonic-producer.md) and enforced per request; it is not inferred from the shape of the publish body.

## Setup

- Producer `{producer_id}` is registered in monotonic mode. Its `last_sequence` for `(producer_id, "acme.orders.v1", 0)` is currently `7`.
- The event's `subject` hashes to partition `0`.

## Request

`meta.sequence` jumps from `7` to `12`, leaving a gap. `meta.previous` is absent.

```http
POST /v1/events HTTP/1.1
Host: broker.example.com
Authorization: Bearer <tenant-token>
Content-Type: application/json

{
  "id": "d0000000-0000-0000-0000-000000000012",
  "type": "gts.cf.core.events.event.v1~acme.orders.created.v1~",
  "tenant_id": "<tenant-uuid>",
  "source": "order-service",
  "subject": "order-mono",
  "subject_type": "gts.cf.core.events.subject.v1~acme.order.v1",
  "occurred_at": "2026-05-29T10:07:00Z",
  "data": { "order_id": "order-mono", "total_cents": 700 },
  "meta": { "version": 1, "producer_id": "{producer_id}", "sequence": 12 }
}
```

## Expected response

- `202 Accepted` - `12 > 7`, so the event is admitted. The size of the gap is not checked.

## Side effects

- The producer chain's `last_sequence` for `({producer_id}, "acme.orders.v1", 0)` advances from `7` to `12`. It is set to the submitted value, not incremented.
- The skipped values `8`-`11` are never admitted later: a subsequent publish carrying any of them is a duplicate by the rule in [negative-1.11](./1.11-negative-monotonic-sequence-not-advanced.md).
- `meta` is stripped on read - consumers never see `producer_id` / `sequence`.
