# Monotonic-mode publish carrying `meta.previous` is rejected

`meta.previous` is a chained-mode field. A producer registered in monotonic mode must omit it, and a publish that includes it is rejected `400 Invalid Argument` as a mode-shape violation - before any sequence comparison, so nothing is admitted and `last_sequence` does not move.

The field is rejected rather than ignored. Accepting it silently would let a producer submit chained-shaped bodies against a monotonic registration and believe a chain was being enforced when none was, which is precisely the guarantee mode selection exists to make explicit. Mode is fixed at [registration](./1.02-positive-register-monotonic-producer.md) and is never inferred from the body.

## Setup

- Producer `{producer_id}` is registered in monotonic mode. Its `last_sequence` for `(producer_id, "acme.orders.v1", 0)` is currently `7`.
- The event's `subject` hashes to partition `0`.

## Request

`meta.sequence` would be acceptable on its own (`8 > 7`), but `meta.previous` is present.

```http
POST /v1/events HTTP/1.1
Host: broker.example.com
Authorization: Bearer <tenant-token>
Content-Type: application/json

{
  "id": "d0000000-0000-0000-0000-000000000008",
  "type": "gts.cf.core.events.event.v1~acme.orders.created.v1~",
  "tenant_id": "<tenant-uuid>",
  "source": "order-service",
  "subject": "order-mono",
  "subject_type": "gts.cf.core.events.subject.v1~acme.order.v1",
  "occurred_at": "2026-05-29T10:07:00Z",
  "data": { "order_id": "order-mono", "total_cents": 700 },
  "meta": { "version": 1, "producer_id": "{producer_id}", "previous": 7, "sequence": 8 }
}
```

## Expected response

- `400 Bad Request` (`PD`)
- The violation names the offending field and the rule. It carries no part of the submitted value.

```json
{
  "type": "gts://gts.cf.core.errors.err.v1~cf.core.err.invalid_argument.v1~",
  "title": "Invalid Argument",
  "status": 400,
  "detail": "Request validation failed",
  "instance": "/v1/events",
  "trace_id": "<request-trace-id>",
  "context": {
    "field_violations": [
      {
        "field": "meta.previous",
        "description": "must be absent for a monotonic-mode producer",
        "reason": "field_not_allowed"
      }
    ],
    "resource_type": "gts.cf.core.events.request.v1~"
  }
}
```

## Side effects

- Nothing is admitted; the shape check precedes the sequence comparison, so the otherwise-valid `sequence` `8` is not applied.
- `last_sequence` stays at `7`.

## Notes

The mirror case - a chained-mode producer omitting `meta.previous` - is the same class of mode-shape violation and should reject the same way. It has no scenario of its own yet.

`reason: "field_not_allowed"` is a proposed value; no existing scenario or the Hard-Error Catalog in `DESIGN.md` defines a reason for a field that is present but forbidden. Confirm before implementing.
