# `meta` with only a version is a stateless publish

A `meta` at a supported `meta.version` that names no producer and carries neither `meta.previous` nor `meta.sequence` is treated as if it were absent: the publish is stateless. The broker consults no producer and keeps no chain, so two such events from different senders are each admitted, and neither is taken for a duplicate of the other.

## Setup

- Topic `acme.orders.v1` and event type `acme.orders.created.v1` registered. No producer is involved.

## Request

Two publishes, each with `meta: { "version": 1 }`.

```http
POST /v1/events HTTP/1.1
Host: broker.example.com
Authorization: Bearer <tenant-token>
Content-Type: application/json

{
  "id": "d0000000-0000-0000-0000-000000000018",
  "type": "gts.cf.core.events.event.v1~acme.orders.created.v1~",
  "subject_tenant": "<tenant-uuid>",
  "source": "order-service",
  "subject": "order-1",
  "subject_type": "gts.acme.shop.orders.order.v1~",
  "occurred_at": "2026-05-29T10:07:00Z",
  "data": { "order_id": "order-1", "total_cents": 700 },
  "meta": { "version": 1 }
}
```

```http
POST /v1/events HTTP/1.1
Host: broker.example.com
Authorization: Bearer <tenant-token>
Content-Type: application/json

{
  "id": "d0000000-0000-0000-0000-000000000019",
  "type": "gts.cf.core.events.event.v1~acme.orders.created.v1~",
  "subject_tenant": "<tenant-uuid>",
  "source": "billing-service",
  "subject": "invoice-1",
  "subject_type": "gts.acme.shop.orders.order.v1~",
  "occurred_at": "2026-05-29T10:07:01Z",
  "data": { "order_id": "order-1", "total_cents": 700 },
  "meta": { "version": 1 }
}
```

## Expected response

- `202 Accepted` for each, no body.

## Side effects

- Both events are stored, in publish order: a stream read of the tenant delivers `d0000000-...-0018`, then `d0000000-...-0019`.
