# Monotonic-mode publish that does not advance is a duplicate

In monotonic mode the broker admits an event only when `meta.sequence` is strictly greater than its stored `last_sequence`. A `meta.sequence` equal to or below `last_sequence` is a duplicate: the event is not admitted a second time and `last_sequence` does not move.

Unlike [chained mode](./1.05-negative-chained-sequence-violation.md), this is not a chain break. A monotonic producer makes no claim about what preceded its event, so a value the broker has already passed carries no information that the two are out of step - it is simply a re-send, and the broker absorbs it.

> **Open question for review - the status code.** The equivalent chained-mode case is documented inconsistently: [positive-1.4](./1.04-positive-chain-head-retry-dedup.md) says `202 Accepted`, while `DESIGN.md:2248` says the duplicate returns `200 OK` with the original event. Monotonic dedup should return whatever that resolves to, and this file must be updated to match rather than settling it independently.

## Setup

- Producer `{producer_id}` is registered in monotonic mode. Its `last_sequence` for `(producer_id, "acme.orders.v1", 0)` is currently `12`.
- The event's `subject` hashes to partition `0`.

## Request

`meta.sequence` is `12`, equal to the stored `last_sequence`. A value below it - including one of the values skipped by an earlier gap, such as `9` - behaves identically.

```http
POST /v1/events HTTP/1.1
Host: broker.example.com
Authorization: Bearer <tenant-token>
Content-Type: application/json

{
  "id": "d0000000-0000-0000-0000-000000000013",
  "type": "gts.cf.core.events.event.v1~acme.orders.created.v1~",
  "tenant_id": "<tenant-uuid>",
  "source": "order-service",
  "subject": "order-mono",
  "subject_type": "gts.cf.core.events.subject.v1~acme.order.v1",
  "occurred_at": "2026-05-29T10:08:00Z",
  "data": { "order_id": "order-mono", "total_cents": 700 },
  "meta": { "version": 1, "producer_id": "{producer_id}", "sequence": 12 }
}
```

## Expected response

- Deduplicated, not admitted. Status per the open question above.

## Side effects

- No second event is written; the first event carrying `sequence` `12` remains the only one.
- `last_sequence` stays at `12`.
- No `412 SequenceViolation` is raised - that outcome belongs to chained mode, where a mismatched `meta.previous` proves the producer's view of the chain has diverged. Monotonic mode has no such claim to contradict.
