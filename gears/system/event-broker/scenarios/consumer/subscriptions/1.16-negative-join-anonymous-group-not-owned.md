# JOIN of an anonymous group by a principal that did not create it → 403 ConsumerGroupNotOwned

An anonymous consumer group belongs to the principal that created it (`POST /v1/consumer-groups`): its subject in its tenant, recorded as the group's `owner_principal` and `tenant`. Only that principal may JOIN it. Another principal, another subject of the same tenant or the same subject in another tenant, is refused with `403 Permission Denied` (`ConsumerGroupNotOwned`) right after the group lookup, before any policy call. Consumers under different principals that share a group need a named group (not yet implemented, tracked in #5702).

## Setup

- The deployment authenticates with static tokens. `<principal-a-token>` and `<principal-b-token>` are bound to two subjects of the same tenant `{tenant_id}`.
- Principal A creates a group `{group_id}` (`POST /v1/consumer-groups`) and JOINs it with one interest on `gts.cf.core.events.topic.v1~acme.orders.v1` for `{tenant_id}` → `{sub_id}`.

## Request (principal B)

```http
POST /v1/subscriptions HTTP/1.1
Host: broker.example.com
Authorization: Bearer <principal-b-token>
Content-Type: application/json

{
  "consumer_group": "{group_id}",
  "client_agent": "worker/1.0.0",
  "interests": [
    {
      "topic": "gts.cf.core.events.topic.v1~acme.orders.v1",
      "subject_tenant": "{tenant_id}",
      "ownership_filter": "entire_tenant",
      "types": ["gts.cf.core.events.event.v1~acme.orders.*"]
    }
  ]
}
```

## Expected response

- `403 Permission Denied` (`ConsumerGroupNotOwned`)

```json
{
  "type": "gts://gts.cf.core.errors.err.v1~cf.core.err.permission_denied.v1~",
  "title": "Permission Denied",
  "status": 403,
  "detail": "You do not have permission to perform this operation",
  "instance": "/v1/subscriptions",
  "trace_id": "<request-trace-id>",
  "context": {
    "reason": "consumer group '{group_id}' was created by another principal",
    "resource_type": "gts.cf.core.events.consumer_group.v1~"
  }
}
```

## Side effects

- No subscription is created: `{sub_id}` is the only subscription of `{group_id}` in principal A's `GET /v1/subscriptions`.
- `{sub_id}` stays a member of `{group_id}`: the refused JOIN does not rebalance the group or evict A's member, even one whose stream has closed. Principal A's `GET /v1/subscriptions/{sub_id}` answers `200` until that member's own expiry removes it (the join timeout before its first stream, its `session_timeout` after a stream closes).
