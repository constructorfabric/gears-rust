# JOIN for an exact subject type the consume scope excludes → 403

An interest's `subject_types` is a delivery filter, not a grant. The broker asks the policy for `consume` on the topic once per group, naming the subject types the matching registered event types allow. An exact subject type the interest selects is checked when it overlaps what one of those event types allows: an allowed pattern covers it, or it covers an allowed pattern (an exact type at or below it, or a narrower wildcard). A policy constraint admits the selector when it has no subject-type condition, or when some subject type is named by every subject-type condition of that constraint, is covered by the selector (the type itself, a type derived from it, or a minor version of it), and is allowed by one of those event types. When no constraint of the scope the policy answers admits the selector, the interest can never receive an event, so the JOIN is refused `403 SubjectTypeNotAuthorized`, naming the subject type. A subject type that neither covers nor is covered by anything those event types allow, including one that shares only some types with an allowed pattern (for example through a minor version), and wildcard subject-type patterns, are not checked.

## Setup

- Tenant tree: `T123` (the caller's tenant) has the child `T234`.
- Topic `gts.cf.core.events.topic.v1~acme.orders.topic.v1` has the registered event type `gts.cf.core.events.event.v1~acme.orders.created.v1~`, which allows the subject types `gts.acme.shop.orders.order.v1~` and `gts.acme.shop.orders.invoice.v1~`.
- The caller, in `T123`, holds `consume` on the topic in `T234` for the subject type `gts.acme.shop.orders.invoice.v1~` only, and `consume` on consumer groups.
- Group `{group_id}` exists, created by the caller.

## Request

```http
POST /v1/subscriptions HTTP/1.1
Host: broker.example.com
Authorization: Bearer <T123-token>
Content-Type: application/json

{
  "consumer_group": "{group_id}",
  "client_agent": "worker/1.0.0",
  "interests": [
    {
      "topic": "gts.cf.core.events.topic.v1~acme.orders.topic.v1",
      "subject_tenant": "<T234-uuid>",
      "ownership_filter": "entire_tenant",
      "types": ["gts.cf.core.events.event.v1~acme.orders.created.v1~"],
      "subject_types": ["gts.acme.shop.orders.order.v1~"]
    }
  ]
}
```

## Expected response

- `403 Permission Denied` (`SubjectTypeNotAuthorized`)

```json
{
  "type": "gts://gts.cf.core.errors.err.v1~cf.core.err.permission_denied.v1~",
  "title": "Permission Denied",
  "status": 403,
  "detail": "You do not have permission to perform this operation",
  "instance": "/v1/subscriptions",
  "trace_id": "<request-trace-id>",
  "context": {
    "reason": "calling principal lacks consume on subject type 'gts.acme.shop.orders.order.v1~'",
    "resource_type": "gts.cf.core.events.request.v1~"
  }
}
```

## Side effects

- No subscription is created; `GET /v1/subscriptions` for `{group_id}` lists none.
