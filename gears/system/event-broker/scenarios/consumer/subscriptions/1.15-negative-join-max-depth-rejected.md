# JOIN rejected for an interest that sends `max_depth`

`max_depth` is not part of an interest: `ownership_filter` decides which tenants and owners an interest reads. A JOIN whose interest still sends `max_depth`, with any value, is rejected with `400 InvalidBody` naming the field and its replacement, and no subscription is created.

## Setup

- Group `{group_id}` exists.
- Topic `gts.cf.core.events.topic.v1~acme.orders.topic.v1` is registered.

## Request

```http
POST /v1/subscriptions HTTP/1.1
Host: broker.example.com
Authorization: Bearer <tenant-token>
Content-Type: application/json

{
  "consumer_group": "{group_id}",
  "client_agent": "worker/1.0.0",
  "interests": [
    {
      "topic": "gts.cf.core.events.topic.v1~acme.orders.topic.v1",
      "subject_tenant": "<tenant-uuid>",
      "ownership_filter": "entire_tenant",
      "max_depth": 0,
      "types": ["gts.cf.core.events.event.v1~acme.orders.created.v1~"]
    }
  ]
}
```

## Expected response

- `400 Bad Request` (`PD`)
- Wire-level code `InvalidBody`.

```json
{
  "type": "gts://gts.cf.core.errors.err.v1~cf.core.err.invalid_argument.v1~",
  "title": "Invalid Argument",
  "status": 400,
  "detail": "InvalidBody: 'max_depth' is not supported; use 'ownership_filter'",
  "instance": "/v1/subscriptions",
  "trace_id": "<request-trace-id>",
  "context": {
    "format": "InvalidBody: 'max_depth' is not supported; use 'ownership_filter'",
    "resource_type": "gts.cf.core.events.request.v1~"
  }
}
```

## Side effects

- No subscription is created.
- No authorization call is made.
- Any other unknown interest field is a data error and gets `422`; `max_depth` alone is answered `400` with this message.
