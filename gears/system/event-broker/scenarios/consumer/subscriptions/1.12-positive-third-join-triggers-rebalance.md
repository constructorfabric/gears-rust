# Third consumer JOINs - ranked four-partition rebalance

A, B and C JOIN one four-partition topic in that order. The broker generates each
subscription UUID, and the assignment uses UUID byte order.

## Setup

Use the Event Broker E2E fixture. It supplies topic
`gts.cf.core.events.topic.v1~cf.e2e.event_broker.four_part.v1`, partitions 0 through 3,
the derived event type shown below, and the owner bearer for subject tenant
`00000000-0000-0000-0000-000000000002`. The standalone demo provisions a different topic.
Use the fixture's broker address and owner bearer for all requests.

Create an anonymous group with `POST /event-broker/v1/consumer-groups`. Take `{group_id}`
from the returned `Location` and body `id`, and confirm the same group with
`GET /event-broker/v1/consumer-groups/{group_id}`.

Before the JOINs, read `GET /event-broker/v1/topics/segments?topic={topic}&partition={partition}`
as the owner for each partition. Record each manifest's `end_sequence` as its head.
Keep the topic quiet through the replay.

Use the request below for each JOIN, setting `client_agent` to `three-reader-A`,
`three-reader-B`, or `three-reader-C`. Record each member's actual `id` and `created_at`
from its JOIN response. For each new member, send `POST /event-broker/v1/subscriptions/{id}:seek`
with its JOIN `topology_version` and a `positions` map keyed by the topic. Include
`{"partition": p, "value": "latest"}` for every partition assigned to that member.
The SEEK response gives the observed head for each partition. Open
`GET /event-broker/v1/events:sse?subscription={id}` with `Accept: text/event-stream`.
Check that the opening `topology` frame carries the JOIN version and full assigned
set with each partition's `offset` and `last_examined` equal to its head.

A owns `[0, 1, 2, 3]` at v1. After B JOINs, let L and H be the members of A and B with
the lower and higher returned UUID, respectively, compared by UUID bytes.
At v2, L owns `[0, 1]` and H owns `[2, 3]`. B SEEKs and opens its stream at v2.
A loses two partitions and receives a full v2 `topology` for its retained assignment
on its existing stream. Read both v2 snapshots before C JOINs.

## Request (instance C)

```http
POST /event-broker/v1/subscriptions HTTP/1.1
Host: broker.example.com
Authorization: Bearer <tenant-token>
Content-Type: application/json

{
  "consumer_group": "{group_id}",
  "client_agent": "three-reader-C",
  "session_timeout": "PT30S",
  "interests": [
    {
      "topic": "gts.cf.core.events.topic.v1~cf.e2e.event_broker.four_part.v1",
      "subject_tenant": "00000000-0000-0000-0000-000000000002",
      "ownership_filter": "entire_tenant",
      "types": [
        "gts.cf.core.events.event.v1~cf.e2e.event_broker.four_part.v1~"
      ]
    }
  ]
}
```

## Expected response (instance C)

- `201 Created`, `Content-Type: application/json`, and
  `Location: /event-broker/v1/subscriptions/{sub_c}`.

The full body below shows `C < L < H`. Substitute C's recorded `id` for `{sub_c}`,
C's recorded `created_at` for `{created_at_c}`, and the created group id for `{group_id}`.
For other ranks, use one `assigned` entry per partition in the C column below,
in ascending partition order.

```json
{
  "id": "{sub_c}",
  "consumer_group": "{group_id}",
  "client_agent": "three-reader-C",
  "interests": [
    {
      "topic": "gts.cf.core.events.topic.v1~cf.e2e.event_broker.four_part.v1",
      "subject_tenant": "00000000-0000-0000-0000-000000000002",
      "ownership_filter": "entire_tenant",
      "barrier_mode": "respect",
      "types": [
        "gts.cf.core.events.event.v1~cf.e2e.event_broker.four_part.v1~"
      ],
      "filter": null,
      "unmatched_types": []
    }
  ],
  "assigned": [
    {
      "topic": "gts.cf.core.events.topic.v1~cf.e2e.event_broker.four_part.v1",
      "partition": 0
    }
  ],
  "topology_version": 3,
  "created_at": "{created_at_c}"
}
```

## Side effects

Compare C's returned UUID bytes with L and H. Each partition belongs to exactly
one subscription. All assignments in the table are at v3.

| Third JOIN rank | L (was `[0, 1]`) | H (was `[2, 3]`) | C |
|---|---|---|---|
| `C < L < H` | `[1]`, continues after loss | `[2, 3]`, continues with the same set | `[0]` |
| `L < C < H` | `[0]`, continues after loss | `[2, 3]`, continues with the same set | `[1]` |
| `L < H < C` | `[0]`, continues after loss | `[1]`, gain ends the old stream with `rebalanced` | `[2, 3]` |

- C SEEKs its assigned partitions at v3 and opens with a full v3 `topology` frame.
- On strict loss or an unchanged set, the existing stream sends a full v3 `topology`
  frame with the retained partitions and their positions. Each position carries
  the recorded head as both `offset` and `last_examined` in this quiet interval.
- If H gains partition 1, its old stream sends a final `control` frame with
  `code: "terminal"`, `reason: "rebalanced"`, and the positions for its old
  partitions `[2, 3]`, then ends.
- Authorized `GET /event-broker/v1/subscriptions/{id}` reads for all three show v3
  and the assignments in the table. The continuing streams still send heartbeats.

## Replay

Run from the repository root. The test starts the authenticated fixture, provisions
the four-partition topic, and checks the rank produced by that run.

```bash
make py-env e2e-event-broker-build
EB_E2E_BACKEND=memory E2E_CLUSTER_MODE=memory \
  E2E_BINARY="$PWD/target/eb-e2e/cf-gears-event-broker-server" \
  E2E_FLIGHT_CONTROL_BINARY="$PWD/target/debug/test-flight-control" \
  .venv/bin/python -m pytest -q \
  testing/e2e/suites/event_broker/test_consumer_subscriptions.py::test_third_join_triggers_rebalance
```
