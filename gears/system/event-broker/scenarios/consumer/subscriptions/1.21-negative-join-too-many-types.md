# JOIN rejected for an interest with too many types

An interest may declare at most 32 event-type selectors in `types`. An interest with more is rejected with `400 TooManyTypes` before any authorization call, and no subscription is created.

## Setup

- Group `{group_id}` exists.
- Topic `gts.cf.core.events.topic.v1~acme.orders.topic.v1` is registered.

## Request

```http
POST /v1/subscriptions HTTP/1.1
Host: broker.example.com
Authorization: Bearer <tenant-token>
Content-Type: application/json

{
  "consumer_group": "{group_id}",
  "client_agent": "worker/1.0.0",
  "interests": [
    {
      "topic": "gts.cf.core.events.topic.v1~acme.orders.topic.v1",
      "subject_tenant": "<tenant-uuid>",
      "ownership_filter": "entire_tenant",
      "types": ["gts.cf.core.events.event.v1~acme.orders.created.v1~"]
    },
    {
      "topic": "gts.cf.core.events.topic.v1~acme.orders.topic.v1",
      "subject_tenant": "<tenant-uuid>",
      "ownership_filter": "entire_tenant",
      "types": [ "...33 event-type selectors..." ]
    }
  ]
}
```

(The second interest's `types` array carries 33 entries; abbreviated here.)

## Expected response

- `400 Bad Request` (`PD`)
- Wire-level code `TooManyTypes`.

```json
{
  "type": "gts://gts.cf.core.errors.err.v1~cf.core.err.invalid_argument.v1~",
  "title": "Invalid Argument",
  "status": 400,
  "detail": "TooManyTypes: interest 1: types count 33 exceeds the maximum of 32",
  "instance": "/v1/subscriptions",
  "trace_id": "<request-trace-id>",
  "context": {
    "format": "TooManyTypes: interest 1: types count 33 exceeds the maximum of 32",
    "resource_type": "gts.cf.core.events.request.v1~"
  }
}
```

## Side effects

- No subscription is created.
- No authorization call is made.
- The message names the offending interest by its index in `interests`.
