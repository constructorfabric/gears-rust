# JOIN rejected for an `only_mine` interest that names another tenant

`only_mine`, the default `ownership_filter`, reads the caller's own events in the caller's own tenant. An interest that keeps it and names a `subject_tenant` other than the caller's is rejected with `400 InvalidTenant` before any authorization call, and no subscription is created. Reading another tenant needs `entire_tenant` or `tenant_subtree_included`.

## Setup

- Group `{group_id}` exists.
- Topic `gts.cf.core.events.topic.v1~acme.orders.topic.v1` is registered.
- The caller's token names tenant `<caller-tenant-uuid>`; `<other-tenant-uuid>` is a different tenant.

## Request

```http
POST /v1/subscriptions HTTP/1.1
Host: broker.example.com
Authorization: Bearer <tenant-token>
Content-Type: application/json

{
  "consumer_group": "{group_id}",
  "client_agent": "worker/1.0.0",
  "interests": [
    {
      "topic": "gts.cf.core.events.topic.v1~acme.orders.topic.v1",
      "subject_tenant": "<other-tenant-uuid>",
      "types": ["gts.cf.core.events.event.v1~acme.orders.created.v1~"]
    }
  ]
}
```

## Expected response

- `400 Bad Request` (`PD`)
- Wire-level code `InvalidTenant`.

```json
{
  "type": "gts://gts.cf.core.errors.err.v1~cf.core.err.invalid_argument.v1~",
  "title": "Invalid Argument",
  "status": 400,
  "detail": "InvalidTenant: interest 0: only_mine reads the caller's own tenant",
  "instance": "/v1/subscriptions",
  "trace_id": "<request-trace-id>",
  "context": {
    "format": "InvalidTenant: interest 0: only_mine reads the caller's own tenant",
    "resource_type": "gts.cf.core.events.request.v1~"
  }
}
```

## Side effects

- No subscription is created.
- No authorization call is made.
- The same interest with `"ownership_filter": "entire_tenant"` is not refused here; the policy then decides whether the caller may read `<other-tenant-uuid>`.
- The message names the offending interest by its index in `interests` (`interest 1: ...` for the second).
