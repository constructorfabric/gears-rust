# Flow: a leave makes a survivor gain - terminate (not yet answered as terminated, tracked in #5977) + re-JOIN

The inverse of [flow-1.1](1.01-flow-two-consumer-rebalance.md). Group `{group_id}` has A=`[0,1]` and B=`[2,3]`, both streaming `gts.cf.core.events.topic.v1~acme.orders.v1` (4 partitions). B leaves; the rebalance assigns B's partitions to A. Because A **gains** partitions and a gained partition has no read position in A's open stream (SEEK is pre-stream-only), A's subscription **terminates** via a `control` frame with `code: "terminal"` (not yet answered as terminated, tracked in #5977; today the stream ends and the subscription stays a group member until A's re-JOIN evicts it, see Exchange 5), and the broker ends the response; A re-JOINs, SEEKs, and reopens. Strictly broker-observable.

---

## Exchange 1 — Consumer B LEAVEs

```http
DELETE /v1/subscriptions/<sub_b> HTTP/1.1
Host: broker.example.com
Authorization: Bearer <tenant-token>
```

```http
HTTP/1.1 204 No Content
```

The broker rebalances the group: A is assigned all 4 partitions (`topology_version` `2 → 3`).

## Exchange 2 — A's open stream receives a terminal control frame, then closes

Because A's new assignment **grows** (`[0,1]` → `[0,1,2,3]`), the broker terminates A's subscription (not yet answered as terminated, tracked in #5977; today the stream ends and A's subscription stays a group member until A's re-JOIN at Exchange 3 evicts it). The last frame on A's stream is a `control` frame with the final positions of the partitions the stream was reading; the broker then ends the response body, with no closing boundary line after the last part.

```
--eb-frame-<uuid-hex>
Content-Type: application/json

{
  "kind": "control",
  "code": "terminal",
  "positions": [
    { "topic": "gts.cf.core.events.topic.v1~acme.orders.v1", "partition": 0, "offset": 110, "last_examined": 110 },
    { "topic": "gts.cf.core.events.topic.v1~acme.orders.v1", "partition": 1, "offset": 8, "last_examined": 96 }
  ],
  "reason": "rebalanced"
}
```

A commits these positions to its own offset store. (Partition `1` shows `last_examined = 96 > offset = 8` — a filter-saturated partition; A re-SEEKs `1` to `96` to skip the server-side-filtered events.)

## Exchange 3 — A re-JOINs (new subscription)

```http
POST /v1/subscriptions HTTP/1.1
Host: broker.example.com
Authorization: Bearer <tenant-token>
Content-Type: application/json

{
  "consumer_group": "{group_id}",
  "client_agent": "order-worker/1.4.0",
  "interests": [ { "topic": "gts.cf.core.events.topic.v1~acme.orders.v1", "subject_tenant": "<tenant-uuid>", "ownership_filter": "entire_tenant", "types": ["gts.cf.core.events.event.v1~acme.orders.*"] } ]
}
```

```http
HTTP/1.1 201 Created
Location: /v1/subscriptions/<sub_a2>
Content-Type: application/json

{
  "id": "<sub_a2>",
  "consumer_group": "{group_id}",
  "client_agent": "order-worker/1.4.0",
  "interests": [
    {
      "topic": "gts.cf.core.events.topic.v1~acme.orders.v1",
      "subject_tenant": "<tenant-uuid>",
      "ownership_filter": "entire_tenant",
      "barrier_mode": "respect",
      "types": ["gts.cf.core.events.event.v1~acme.orders.*"],
      "filter": null,
      "unmatched_types": []
    }
  ],
  "assigned": [
    { "topic": "gts.cf.core.events.topic.v1~acme.orders.v1", "partition": 0 },
    { "topic": "gts.cf.core.events.topic.v1~acme.orders.v1", "partition": 1 },
    { "topic": "gts.cf.core.events.topic.v1~acme.orders.v1", "partition": 2 },

  ],
  "topology_version": 4,
  "created_at": "2026-05-29T10:05:00Z"
}
```

A new `subscription_id` is issued. The re-JOIN evicts the disconnected `<sub_a>` and rebalances the group, so `topology_version` advances `3 -> 4`. The group's stored cursors are untouched by the churn and hold only what earlier SEEKs wrote.

## Exchange 4 - A SEEKs all four from the group's own progress store, then reopens

```http
POST /v1/subscriptions/<sub_a2>:seek HTTP/1.1
Host: broker.example.com
Authorization: Bearer <tenant-token>
Content-Type: application/json

{
  "topology_version": 4,
  "positions": {
    "gts.cf.core.events.topic.v1~acme.orders.v1": [
      { "partition": 0, "value": 110 },
      { "partition": 1, "value": 96 },
      { "partition": 2, "value": "<recorded_2>" },
      { "partition": 3, "value": "<recorded_3>" }
    ]
  }
}
```

`<recorded_2>` and `<recorded_3>` stand for integer offsets (a string value is a SEEK sentinel). A partition with no recorded position is SEEKed `earliest` (redelivery) or `latest` (skip); durable progress is the consumer's own (ADR-0006).

```http
HTTP/1.1 200 OK
Content-Type: application/json

{
  "positions": {
    "gts.cf.core.events.topic.v1~acme.orders.v1": [
      { "partition": 0, "value": 110 },
      { "partition": 1, "value": 96 },
      { "partition": 2, "value": "<recorded_2>" },
      { "partition": 3, "value": "<recorded_3>" }
    ]
  }
}
```

A then opens `GET /v1/events:stream?subscription=<sub_a2>` and receives the open-time `topology` baseline followed by events.

## Exchange 5 — reuse of the old subscription_id is rejected

```http
GET /v1/events:stream?subscription=<sub_a> HTTP/1.1
Host: broker.example.com
Authorization: Bearer <tenant-token>
Accept: multipart/mixed
```

```http
HTTP/1.1 404 Not Found
Content-Type: application/problem+json

{
  "type": "gts://gts.cf.core.errors.err.v1~cf.core.err.not_found.v1~",
  "title": "Not Found",
  "status": 404,
  "detail": "subscription '<sub_a>' does not exist",
  "instance": "/v1/events:stream",
  "trace_id": "<request-trace-id>",
  "context": {
    "resource_type": "gts.cf.core.events.subscription.v1~",
    "resource_name": "<sub_a>"
  }
}
```

`410 SubscriptionTerminated` (not yet answered, tracked in #5977; here A's re-JOIN at Exchange 3 evicted `<sub_a>`, so the reuse answers `404 SubscriptionNotFound`) - the old `subscription_id` terminated at Exchange 2. (Safety net for a consumer that missed the terminal control frame.)

---

## Side effects (cumulative)

- `topology_version` advances `2 → 4` (B's LEAVE, then A's re-JOIN).
- `<sub_b>` is removed (LEAVE); `<sub_a>` is terminated (gain) (not yet answered as terminated, tracked in #5977; today A's re-JOIN at Exchange 3 evicts it, see Exchange 5); `<sub_a2>` holds `[0,1,2,3]`.
- A reads `2,3` from the positions the consumers recorded in their own store; the broker's stored cursor for `2,3` is only the position B SEEKed to, since delivery does not move it.
- A reaches `2,3` only after terminate (not yet answered as terminated, tracked in #5977: A's stream ends, and A may reopen `<sub_a>` until its `session_timeout` ends or a JOIN to the group evicts it), re-JOIN, SEEK and reopen, strictly after B stopped; an event B processed but did not record is delivered again to A (at-least-once).
