# Flow: PositionsNotSet recovery

The full HTTP transcript of the recovery sequence when a client opens the stream before seeding a partition: the broker replies `409 PositionsNotSet`, the client SEEKs the listed partitions, and the retried stream succeeds.

Every exchange is shown inline. This is the broker-observable recovery sequence. Client-side retry policy and retry budgets are SDK behavior and are outside this scenario file.

Subscription `{sub_id}` has JOINed group `{group_id}` and is assigned `("acme.orders.v1", 0)`; no SEEK has happened yet.

---

## Exchange 1 — Open the stream without seeding (rejected)

```http
GET /v1/events:stream?subscription={sub_id} HTTP/1.1
Host: broker.example.com
Authorization: Bearer <tenant-token>
Accept: multipart/mixed
```

```http
HTTP/1.1 409 Conflict
Content-Type: application/problem+json

{
  "type": "gts://gts.cf.core.errors.err.v1~cf.core.err.failed_precondition.v1~",
  "title": "Failed Precondition",
  "status": 409,
  "detail": "Operation precondition not met",
  "instance": "/v1/events:stream",
  "trace_id": "<request-trace-id>",
  "context": {
    "resource_type": "gts.cf.core.events.subscription.v1~",
    "violations": [
      {
        "type": "positions_not_set",
        "subject": "gts.cf.core.events.topic.v1~acme.orders.v1:0",
        "description": "call POST /v1/subscriptions/{sub_id}:seek before re-opening the stream"
      }
    ]
  }
}
```

## Exchange 2 — SEEK the unseeded partitions

The client SEEKs exactly the partitions named by the violations' `subject` values, each of which is a `<topic-id>:<partition>` pair:

```http
POST /v1/subscriptions/{sub_id}:seek HTTP/1.1
Host: broker.example.com
Authorization: Bearer <tenant-token>
Content-Type: application/json

{
  "topology_version": 1,
  "positions": {
    "gts.cf.core.events.topic.v1~acme.orders.v1": [
      { "partition": 0, "value": "earliest" }
    ]
  }
}
```

```http
HTTP/1.1 200 OK
Content-Type: application/json

{ "positions": { "gts.cf.core.events.topic.v1~acme.orders.v1": [ { "partition": 0, "value": 99 } ] } }
```

## Exchange 3 — Retry the stream (succeeds)

```http
GET /v1/events:stream?subscription={sub_id} HTTP/1.1

Authorization: Bearer <tenant-token>
Accept: multipart/mixed
```

---

## Side effects

- After Exchange 1: no stream established, stored cursor for `(group, "acme.orders.v1", 0)` still absent (the 409 changes nothing).
- After Exchange 2: stored cursor for `(group, "acme.orders.v1", 0)` is set to `99`.
- After Exchange 3: `subsequent GET /v1/events:stream returns 200`; emission begins at sequence `100`.
- `metric stream_positions_not_set incremented by 1` (the broker counts the rejected open; not yet implemented, tracked in #5983).
