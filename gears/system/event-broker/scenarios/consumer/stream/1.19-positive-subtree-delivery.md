# Subtree delivery reads the caller's tenant and the tenants below it

An interest with `"ownership_filter": "tenant_subtree_included"` reads its `subject_tenant` and every tenant below it in the tenant tree, as far as the policy lets the caller reach. `subject_tenant` names the root of the subtree, the caller's own tenant when absent; it is not the tenant of every delivered event, so an event of a child tenant keeps its own `subject_tenant`. Owners do not matter: tenant-wide and owned events are delivered alike. A tenant outside the subtree is not delivered.

## Setup

- Tenant tree: `T123` (the caller's tenant) has the child `T234`; `T999` is not below `T123`.
- The caller, in `T123`, holds `consume` on `gts.cf.core.events.topic.v1~acme.orders.topic.v1` for its subtree and `consume` on consumer groups.
- Event type `gts.cf.core.events.event.v1~acme.orders.created.v1~` on that topic (1 partition).
- [Cold JOIN](../subscriptions/1.01-positive-cold-join-fresh-group.md) of a fresh group with the interest below, then [SEEK earliest](../positions/1.01-positive-seek-earliest.md) → seeded `{sub_id}`. The JOIN `201` echoes `"subject_tenant": "<T123-uuid>"` and `"ownership_filter": "tenant_subtree_included"`.

```json
{
  "topic": "gts.cf.core.events.topic.v1~acme.orders.topic.v1",
  "ownership_filter": "tenant_subtree_included",
  "types": ["gts.cf.core.events.event.v1~acme.orders.created.v1~"]
}
```

- Two events of the type are published, in this order: event A for `<T999-uuid>`, then event B for `<T234-uuid>`. Neither has a `subject_owner`.

## Request

```http
GET /v1/events:stream?subscription={sub_id} HTTP/1.1
Host: broker.example.com
Authorization: Bearer <tenant-token>
Accept: multipart/mixed
```

## Expected response

- `200 OK`, `Content-Type: multipart/mixed; boundary=<...>`.
- The `topology` frame assigns the interest's topic and partition.
- The first `event` frame is event B, with its own tenant. Event A is never delivered.

```
--<boundary>
Content-Type: application/json

{ "kind": "event", "payload": { "id": "<event-b-id>", "type": "gts.cf.core.events.event.v1~acme.orders.created.v1~", "subject_tenant": "<T234-uuid>", "partition": 0, "sequence": <n>, ... } }
```

## Side effects

- `subscription {sub_id} next frame is event <event-b-id>`: the topic has one partition and A was stored first, so a stream that ignored the subtree would deliver A first.
- A self-managed child behind a barrier is read only with `"barrier_mode": "ignore"` and the right to cross it.
