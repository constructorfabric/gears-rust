# Base type selector delivers types two levels below it

A bare type id covers its derived types at any depth: the interest's `types` entries are matched with GTS pattern semantics against the whole chain of the event's `type`. An interest naming a base type is delivered a type derived from it and a type derived from that one.

## Setup

- Topic `gts.cf.core.events.topic.v1~acme.orders.x.orders.v1` (1 partition) has a chain of event types, each schema's `allOf` referring to the one before:
  - the base `gts.cf.core.events.event.v1~acme.orders.x.created.v1~`;
  - `gts.cf.core.events.event.v1~acme.orders.x.created.v1~acme.orders.x.express.v1~`, derived from the base;
  - `gts.cf.core.events.event.v1~acme.orders.x.created.v1~acme.orders.x.express.v1~acme.orders.x.priority.v1~`, derived from `...express.v1~`.
- [Cold JOIN](../subscriptions/1.01-positive-cold-join-fresh-group.md) with one interest, then [SEEK earliest](../positions/1.01-positive-seek-earliest.md) → seeded `{sub_id}`:

```json
{
  "topic": "gts.cf.core.events.topic.v1~acme.orders.x.orders.v1",
  "subject_tenant": "<tenant-uuid>",
  "ownership_filter": "entire_tenant",
  "types": ["gts.cf.core.events.event.v1~acme.orders.x.created.v1~"]
}
```

## Request

```http
GET /v1/events:stream?subscription={sub_id} HTTP/1.1
Host: broker.example.com
Authorization: Bearer <tenant-token>
Accept: multipart/mixed
```

Once the stream is open, three events are published for `<tenant-uuid>`, in this order: A of `...express.v1~`, B of `...express.v1~acme.orders.x.priority.v1~`, then C of the base.

## Expected response

- `200 OK`, `Content-Type: multipart/mixed; boundary=<...>`.
- The `topology` frame assigns the interest's topic and partition.
- The `event` frames are A, B and C, in that order.

```
--<boundary>
Content-Type: application/json

{ "kind": "event", "payload": { "id": "<event-a-id>", "type": "gts.cf.core.events.event.v1~acme.orders.x.created.v1~acme.orders.x.express.v1~", "partition": 0, "sequence": <sequence>, ... } }
--<boundary>
Content-Type: application/json

{ "kind": "event", "payload": { "id": "<event-b-id>", "type": "gts.cf.core.events.event.v1~acme.orders.x.created.v1~acme.orders.x.express.v1~acme.orders.x.priority.v1~", "partition": 0, "sequence": <sequence>, ... } }
--<boundary>
Content-Type: application/json

{ "kind": "event", "payload": { "id": "<event-c-id>", "type": "gts.cf.core.events.event.v1~acme.orders.x.created.v1~", "partition": 0, "sequence": <sequence>, ... } }
```

## Side effects

- None beyond the delivery: the selector changes only which events are delivered.
