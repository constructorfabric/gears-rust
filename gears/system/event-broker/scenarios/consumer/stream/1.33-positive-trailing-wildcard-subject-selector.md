# Trailing-wildcard subject-type selector delivers only its prefix

An interest's `subject_types` entries are matched with GTS pattern semantics: a trailing `*` covers its prefix. A selector made of a base subject type followed by a vendor and `*` (`gts.acme.orders.x.customer.v1~acme.*`) covers the subject types derived from that base under that vendor only. It covers neither the bare base itself, nor a subject type derived from the base under another vendor, nor another subject type.

## Setup

- Event type `gts.cf.core.events.event.v1~acme.orders.x.created.v1~` on topic `gts.cf.core.events.topic.v1~acme.orders.x.orders.v1` (1 partition) allows subject types `gts.acme.orders.x.customer.v1~` (with its derived subject types) and `gts.acme.orders.x.supplier.v1~`.
- [Cold JOIN](../subscriptions/1.01-positive-cold-join-fresh-group.md) with one interest that names the selector, then [SEEK earliest](../positions/1.01-positive-seek-earliest.md) → seeded `{sub_id}`:

```json
{
  "topic": "gts.cf.core.events.topic.v1~acme.orders.x.orders.v1",
  "subject_tenant": "<tenant-uuid>",
  "ownership_filter": "entire_tenant",
  "types": ["gts.cf.core.events.event.v1~acme.orders.x.created.v1~"],
  "subject_types": ["gts.acme.orders.x.customer.v1~acme.*"]
}
```

## Request

```http
GET /v1/events:stream?subscription={sub_id} HTTP/1.1
Host: broker.example.com
Authorization: Bearer <tenant-token>
Accept: multipart/mixed
```

Once the stream is open, five events of the type are published for `<tenant-uuid>`, in this order:
- A with `subject_type` `gts.acme.orders.x.customer.v1~acme.retail.x.member.v1~` (under the prefix);
- B with `gts.acme.orders.x.supplier.v1~`;
- C with `gts.acme.orders.x.customer.v1~` (the bare base);
- D with `gts.acme.orders.x.customer.v1~globex.retail.x.member.v1~` (another vendor);
- E with `gts.acme.orders.x.customer.v1~acme.retail.x.member.v1~`.

## Expected response

- `200 OK`, `Content-Type: multipart/mixed; boundary=<...>`.
- The `topology` frame assigns the interest's topic and partition.
- The `event` frames are A, then E. Events B, C and D are never delivered.

```
--<boundary>
Content-Type: application/json

{ "kind": "event", "payload": { "id": "<event-a-id>", "type": "gts.cf.core.events.event.v1~acme.orders.x.created.v1~", "subject_type": "gts.acme.orders.x.customer.v1~acme.retail.x.member.v1~", "partition": 0, "sequence": <sequence>, ... } }
--<boundary>
Content-Type: application/json

{ "kind": "event", "payload": { "id": "<event-e-id>", "type": "gts.cf.core.events.event.v1~acme.orders.x.created.v1~", "subject_type": "gts.acme.orders.x.customer.v1~acme.retail.x.member.v1~", "partition": 0, "sequence": <sequence>, ... } }
```

## Side effects

- The topic has one partition and B, C and D were stored before E, so a stream that delivered any of them would deliver it before E.
- Events B, C and D stay stored; a subscription without the selector receives them.
