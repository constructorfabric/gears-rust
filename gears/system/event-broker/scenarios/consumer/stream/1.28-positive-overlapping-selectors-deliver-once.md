# Event matched by two selectors is delivered once

An interest's `types` entries are matched with GTS pattern semantics, and an event is delivered when any one of them matches it. An event that two entries match, such as a derived type named both by itself and through its base (a bare type id covers its derived types), is still delivered as one `event` frame.

## Setup

- Topic `gts.cf.core.events.topic.v1~acme.orders.x.orders.v1` (1 partition) has the base `gts.cf.core.events.event.v1~acme.orders.x.created.v1~` and `gts.cf.core.events.event.v1~acme.orders.x.created.v1~acme.orders.x.express.v1~`, derived from it.
- [Cold JOIN](../subscriptions/1.01-positive-cold-join-fresh-group.md) with one interest naming both, then [SEEK earliest](../positions/1.01-positive-seek-earliest.md) → seeded `{sub_id}`:

```json
{
  "topic": "gts.cf.core.events.topic.v1~acme.orders.x.orders.v1",
  "subject_tenant": "<tenant-uuid>",
  "ownership_filter": "entire_tenant",
  "types": [
    "gts.cf.core.events.event.v1~acme.orders.x.created.v1~",
    "gts.cf.core.events.event.v1~acme.orders.x.created.v1~acme.orders.x.express.v1~"
  ]
}
```

## Request

```http
GET /v1/events:stream?subscription={sub_id} HTTP/1.1
Host: broker.example.com
Authorization: Bearer <tenant-token>
Accept: multipart/mixed
```

Once the stream is open, two events are published for `<tenant-uuid>`, in this order: A of `...express.v1~`, then B of the base.

## Expected response

- `200 OK`, `Content-Type: multipart/mixed; boundary=<...>`.
- The `topology` frame assigns the interest's topic and partition.
- The `event` frames are A, then B: exactly one frame for A.

```
--<boundary>
Content-Type: application/json

{ "kind": "event", "payload": { "id": "<event-a-id>", "type": "gts.cf.core.events.event.v1~acme.orders.x.created.v1~acme.orders.x.express.v1~", "partition": 0, "sequence": <sequence>, ... } }
--<boundary>
Content-Type: application/json

{ "kind": "event", "payload": { "id": "<event-b-id>", "type": "gts.cf.core.events.event.v1~acme.orders.x.created.v1~", "partition": 0, "sequence": <sequence>, ... } }
```

## Side effects

- `subscription {sub_id} next frame is event <event-b-id>` after the frame for A: a second frame for A would come before B on the topic's one partition.
