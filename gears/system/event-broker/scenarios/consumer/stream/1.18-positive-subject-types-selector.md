# Subject-type selector narrows delivery

An interest may carry `subject_types`, a list of 1 to 32 GTS type patterns. The stream then delivers only events whose `subject_type` matches one of them, matched like `types`: a bare type id covers its derived types, a trailing `*` covers its prefix. The selector is a delivery filter. It has no authorization meaning and never widens what the caller may read. An interest without `subject_types` (or with `[]`) delivers every subject type.

## Setup

- Event type `gts.cf.core.events.event.v1~acme.orders.created.v1~` on topic `gts.cf.core.events.topic.v1~acme.orders.topic.v1` (1 partition) allows subject types `gts.acme.orders.x.customer.v1~` and `gts.acme.orders.x.supplier.v1~`.
- [Cold JOIN](../subscriptions/1.01-positive-cold-join-fresh-group.md) with one interest that names the selector, then [SEEK earliest](../positions/1.01-positive-seek-earliest.md) → seeded `{sub_id}`:

```json
{
  "topic": "gts.cf.core.events.topic.v1~acme.orders.topic.v1",
  "subject_tenant": "<tenant-uuid>",
  "ownership_filter": "entire_tenant",
  "types": ["gts.cf.core.events.event.v1~acme.orders.created.v1~"],
  "subject_types": ["gts.acme.orders.x.supplier.v1~"]
}
```

- The JOIN `201` echoes the interest with `"subject_types": ["gts.acme.orders.x.supplier.v1~"]`. An interest without a selector is echoed with no `subject_types` key.

## Request

```http
GET /v1/events:stream?subscription={sub_id} HTTP/1.1
Host: broker.example.com
Authorization: Bearer <tenant-token>
Accept: multipart/mixed
```

Once the stream is open, two events of the type are published for `<tenant-uuid>`, in this order: event A with `subject_type` `gts.acme.orders.x.customer.v1~`, then event B with `subject_type` `gts.acme.orders.x.supplier.v1~`.

## Expected response

- `200 OK`, `Content-Type: multipart/mixed; boundary=<...>`.
- The `topology` frame assigns the interest's topic and partition.
- The first `event` frame is event B. Event A is never delivered.

```
--<boundary>
Content-Type: application/json

{ "kind": "event", "payload": { "id": "<event-b-id>", "type": "gts.cf.core.events.event.v1~acme.orders.created.v1~", "subject_tenant": "<tenant-uuid>", "subject_type": "gts.acme.orders.x.supplier.v1~", "partition": 0, "sequence": <n>, ... } }
```

## Side effects

- `subscription {sub_id} next frame is event <event-b-id>`: the topic has one partition and A was stored first, so a stream that ignored the selector would deliver A first.
- Event A stays stored; another subscription without the selector receives it.
