# Prefix wildcard selector delivers only the types under it

An interest's `types` entries are matched with GTS pattern semantics: a trailing `*` covers its prefix. An entry that ends in a namespace followed by `*` is delivered every event type under that namespace, and not a type of the same topic outside it. The all-types form `gts.cf.core.events.event.v1~*` is [Wildcard event-type stream](1.15-positive-wildcard-event-type-stream.md).

## Setup

- Topic `gts.cf.core.events.topic.v1~acme.orders.x.orders.v1` (1 partition) has three event types: `gts.cf.core.events.event.v1~acme.orders.x.created.v1~` and `gts.cf.core.events.event.v1~acme.orders.x.shipped.v1~` under the `acme.orders.x` namespace, and `gts.cf.core.events.event.v1~acme.billing.x.invoiced.v1~` outside it.
- [Cold JOIN](../subscriptions/1.01-positive-cold-join-fresh-group.md) with one interest, then [SEEK earliest](../positions/1.01-positive-seek-earliest.md) → seeded `{sub_id}`:

```json
{
  "topic": "gts.cf.core.events.topic.v1~acme.orders.x.orders.v1",
  "subject_tenant": "<tenant-uuid>",
  "ownership_filter": "entire_tenant",
  "types": ["gts.cf.core.events.event.v1~acme.orders.x.*"]
}
```

## Request

```http
GET /v1/events:stream?subscription={sub_id} HTTP/1.1
Host: broker.example.com
Authorization: Bearer <tenant-token>
Accept: multipart/mixed
```

Once the stream is open, three events are published for `<tenant-uuid>`, in this order: A of `...acme.orders.x.created.v1~`, B of `...acme.billing.x.invoiced.v1~`, then C of `...acme.orders.x.shipped.v1~`.

## Expected response

- `200 OK`, `Content-Type: multipart/mixed; boundary=<...>`.
- The `topology` frame assigns the interest's topic and partition.
- The `event` frames are A and C, in that order. Event B is never delivered.

```
--<boundary>
Content-Type: application/json

{ "kind": "event", "payload": { "id": "<event-a-id>", "type": "gts.cf.core.events.event.v1~acme.orders.x.created.v1~", "partition": 0, "sequence": <sequence>, ... } }
--<boundary>
Content-Type: application/json

{ "kind": "event", "payload": { "id": "<event-c-id>", "type": "gts.cf.core.events.event.v1~acme.orders.x.shipped.v1~", "partition": 0, "sequence": <sequence>, ... } }
```

## Side effects

- The topic has one partition and B was stored before C, so a stream that delivered B would deliver it before C.
- Event B stays stored; a subscription selecting its type receives it.
