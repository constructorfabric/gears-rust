# Selector matching no type of the topic delivers nothing

A JOIN whose `types` entry matches no event type registered on the topic is not refused: it succeeds, and the `201` lists that entry in the interest's `unmatched_types` (see [JOIN naming an unregistered type](../subscriptions/1.18-positive-join-unregistered-type-reported.md)). Entries are matched with GTS pattern semantics, so a wildcard is reported the same way when no registered type falls under it. The stream then delivers that interest none of the topic's events.

## Setup

- Topic `gts.cf.core.events.topic.v1~acme.orders.x.orders.v1` (1 partition) has three event types: `gts.cf.core.events.event.v1~acme.orders.x.created.v1~`, `gts.cf.core.events.event.v1~acme.orders.x.shipped.v1~` and `gts.cf.core.events.event.v1~acme.orders.x.marker.v1~`. None is under `acme.audit.x`.
- Run [Create an anonymous group](../groups/1.01-positive-create-anonymous-group.md). Group id available as `{group_id}`.
- JOIN with two interests on the topic, for the same tenant: the first names a wildcard that matches no type of the topic; the second names only `...x.marker.v1~`, so a marker event shows how far the stream has read.

```http
POST /v1/subscriptions HTTP/1.1
Host: broker.example.com
Authorization: Bearer <tenant-token>
Content-Type: application/json

{
  "consumer_group": "{group_id}",
  "client_agent": "audit-worker/1.0.0",
  "interests": [
    {
      "topic": "gts.cf.core.events.topic.v1~acme.orders.x.orders.v1",
      "subject_tenant": "<tenant-uuid>",
      "ownership_filter": "entire_tenant",
      "types": ["gts.cf.core.events.event.v1~acme.audit.x.*"]
    },
    {
      "topic": "gts.cf.core.events.topic.v1~acme.orders.x.orders.v1",
      "subject_tenant": "<tenant-uuid>",
      "ownership_filter": "entire_tenant",
      "types": ["gts.cf.core.events.event.v1~acme.orders.x.marker.v1~"]
    }
  ]
}
```

- The JOIN answers `201 Created`. The first interest's `unmatched_types` names the wildcard; the second's is `[]`. Both interests share the topic's one partition.

```json
{
  "id": "{sub_id}",
  "consumer_group": "{group_id}",
  "client_agent": "audit-worker/1.0.0",
  "interests": [
    {
      "topic": "gts.cf.core.events.topic.v1~acme.orders.x.orders.v1",
      "subject_tenant": "<tenant-uuid>",
      "ownership_filter": "entire_tenant",
      "barrier_mode": "respect",
      "types": ["gts.cf.core.events.event.v1~acme.audit.x.*"],
      "filter": null,
      "unmatched_types": ["gts.cf.core.events.event.v1~acme.audit.x.*"]
    },
    {
      "topic": "gts.cf.core.events.topic.v1~acme.orders.x.orders.v1",
      "subject_tenant": "<tenant-uuid>",
      "ownership_filter": "entire_tenant",
      "barrier_mode": "respect",
      "types": ["gts.cf.core.events.event.v1~acme.orders.x.marker.v1~"],
      "filter": null,
      "unmatched_types": []
    }
  ],
  "assigned": [
    { "topic": "gts.cf.core.events.topic.v1~acme.orders.x.orders.v1", "partition": 0 }
  ],
  "topology_version": 1,
  "created_at": "2026-05-29T10:00:00Z"

```

- [SEEK earliest](../positions/1.01-positive-seek-earliest.md) → seeded `{sub_id}`.

## Request

```http
GET /v1/events:stream?subscription={sub_id} HTTP/1.1
Host: broker.example.com
Authorization: Bearer <tenant-token>
Accept: multipart/mixed
```

Once the stream is open, three events are published for `<tenant-uuid>`, in this order: A of `...x.created.v1~`, B of `...x.shipped.v1~`, then C of `...x.marker.v1~`.

## Expected response

- `200 OK`, `Content-Type: multipart/mixed; boundary=<...>`.
- The `topology` frame assigns the topic and partition.
- The first `event` frame is the marker C. Events A and B are never delivered.

```
--<boundary>
Content-Type: application/json

{ "kind": "event", "payload": { "id": "<event-c-id>", "type": "gts.cf.core.events.event.v1~acme.orders.x.marker.v1~", "partition": 0, "sequence": <sequence>, ... } }
```

## Side effects

- `subscription {sub_id} next frame is event <event-c-id>`: the topic has one partition and A and B were stored first, so a stream that delivered them would deliver them before C.
- `unmatched_types` is not stored: [Read subscription](../subscriptions/1.10-positive-read-subscription.md) echoes the interests without it.
