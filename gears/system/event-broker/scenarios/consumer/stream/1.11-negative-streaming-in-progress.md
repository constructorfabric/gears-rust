# Second stream or SEEK on a streaming subscription → 409 StreamingInProgress

At most one `:stream` is open on a `subscription_id` at a time. While it is open, a second `:stream` or a `:seek` on the same `subscription_id` returns `409 StreamingInProgress` once the caller passes the checks that run first (identity, tenant, joiner and group; for a stream also the positions check); a `GET` answers normally, and `DELETE` (the priority interrupt - see [positive-1.13](1.13-positive-delete-while-streaming.md)) ends the stream. The existing stream is unaffected by the refused calls.

## Setup

- Run [Cold JOIN](../subscriptions/1.01-positive-cold-join-fresh-group.md) → `{sub_id}`, SEEK every assigned partition.
- A [stream](1.01-positive-stream-multipart-frames.md) is open against `{sub_id}`.

## Request (a second stream on the same subscription)

```http
GET /v1/events:stream?subscription={sub_id} HTTP/1.1
Host: broker.example.com
Authorization: Bearer <tenant-token>
Accept: multipart/mixed
```

## Expected response

- `409 Conflict` (`PD`)

```json
{
  "type": "gts://gts.cf.core.errors.err.v1~cf.core.err.failed_precondition.v1~",
  "title": "Failed Precondition",
  "status": 409,
  "detail": "Operation precondition not met",
  "instance": "/v1/events:stream",
  "trace_id": "<request-trace-id>",
  "context": {
    "resource_type": "gts.cf.core.events.subscription.v1~",
    "violations": [ { "type": "streaming_in_progress", "subject": "{sub_id}", "description": "one stream per subscription; a second stream or a SEEK is refused while it is open" } ]
  }
}
```

## Side effects

- None. The first stream continues uninterrupted. (A `:seek` on the open stream returns the same `409 StreamingInProgress` to a caller the identity, tenant, joiner and group checks admit - see [positions/negative-1.7](../positions/1.07-negative-seek-while-streaming.md).)
