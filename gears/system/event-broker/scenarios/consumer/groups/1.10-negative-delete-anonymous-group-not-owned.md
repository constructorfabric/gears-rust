# DELETE of an anonymous group by a principal that did not create it → 403 ConsumerGroupNotOwned

An anonymous consumer group belongs to the principal that created it (`POST /v1/consumer-groups`): its subject in its tenant, recorded as the group's `owner_principal` and `tenant`. Only that principal may DELETE it. Another principal, another subject of the same tenant or the same subject in another tenant, is refused with `403 Permission Denied` (`ConsumerGroupNotOwned`). The check runs after the group lookup (an unknown group answers `404`) and the tenant check, and before the active-members check, so a refused principal learns nothing about the group's members.

## Setup

- The deployment authenticates with static tokens. `<principal-a-token>` and `<principal-b-token>` are bound to two subjects of the same tenant `{tenant_id}`.
- Principal A creates a group `{group_id}` (`POST /v1/consumer-groups`).

## Request (principal B)

```http
DELETE /v1/consumer-groups/{group_id} HTTP/1.1
Host: broker.example.com
Authorization: Bearer <principal-b-token>
```

## Expected response

- `403 Permission Denied` (`ConsumerGroupNotOwned`)

```json
{
  "type": "gts://gts.cf.core.errors.err.v1~cf.core.err.permission_denied.v1~",
  "title": "Permission Denied",
  "status": 403,
  "detail": "You do not have permission to perform this operation",
  "instance": "/v1/consumer-groups/{group_id}",
  "trace_id": "<request-trace-id>",
  "context": {
    "reason": "consumer group '{group_id}' was created by another principal",
    "resource_type": "gts.cf.core.events.consumer_group.v1~"
  }
}
```

## Side effects

- `{group_id}` still exists: principal A's `GET /v1/consumer-groups/{group_id}` answers `200`.
