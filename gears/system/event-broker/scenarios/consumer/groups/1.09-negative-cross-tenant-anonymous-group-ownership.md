# Access to an anonymous consumer group by a principal of another tenant is denied

An anonymous consumer group records the tenant and the principal that created it (`tenant` and `owner_principal`). Reads go through the tenant check on the group's tenant: `GET` answers `403 Permission Denied` (`TenantIdNotAuthorized`) to a caller the policy does not let reach that tenant, and `GET /consumer-groups` leaves the group out of that caller's listing. JOIN (`POST /subscriptions`) and `DELETE` require the creating principal in its tenant, its subject and tenant both: anyone else is refused with `403 Permission Denied` (`ConsumerGroupNotOwned`). JOIN checks the creator right after the group lookup, before any policy call, so a principal of another tenant gets `ConsumerGroupNotOwned`; `DELETE` runs the tenant check first, so the same principal gets `TenantIdNotAuthorized`.

Named groups are explicitly excluded from this rule: they are platform resources gated by an explicit permission grant, not by their creator (not yet implemented, tracked in #5702).

## Ownership rules

| Operation | Anonymous group | Named group (not yet implemented, tracked in #5702) |
|---|---|---|
| `GET /consumer-groups/{id}` | 403 `TenantIdNotAuthorized` if the policy does not let the caller reach the group's tenant | Allowed if caller has `:consume` grant |
| `DELETE /consumer-groups/{id}` | 403 `TenantIdNotAuthorized` if the policy does not let the caller reach the group's tenant; otherwise 403 `ConsumerGroupNotOwned` if the caller is not the creating principal in its tenant | Allowed if caller has `:manage` grant |
| `GET /consumer-groups` (list) | Excludes groups of tenants the policy does not let the caller reach | Included if caller has `:consume` grant |
| `POST /subscriptions` (JOIN) | 403 `ConsumerGroupNotOwned` if the caller is not the creating principal in its tenant, before any policy call; then 403 `ConsumerGroupNotAuthorized` if the policy refuses `consume` on the group | Allowed if caller has `:consume` grant |

## Setup

- Principal A of tenant A creates an anonymous consumer group `{group_id}`.
- Principal B of tenant B has a valid, authenticated identity. Tenant B is not tenant A and is not an ancestor of it, so a tree-aware policy does not let B reach tenant A.

## Scenarios

### 1. GET returns 403 TenantIdNotAuthorized

```
GET /v1/consumer-groups/{group_id}
Authorization: Bearer <tenant-b-token>

→ 403 Permission Denied (TenantIdNotAuthorized)
```

```json
{
  "type": "gts://gts.cf.core.errors.err.v1~cf.core.err.permission_denied.v1~",
  "title": "Permission Denied",
  "status": 403,
  "detail": "You do not have permission to perform this operation",
  "instance": "/v1/consumer-groups/{group_id}",
  "trace_id": "<request-trace-id>",
  "context": {
    "reason": "access denied by policy",
    "resource_type": "gts.cf.core.events.request.v1~"
  }
}
```

### 2. DELETE returns 403 TenantIdNotAuthorized

```
DELETE /v1/consumer-groups/{group_id}
Authorization: Bearer <tenant-b-token>

→ 403 Permission Denied (TenantIdNotAuthorized)
```

```json
{
  "type": "gts://gts.cf.core.errors.err.v1~cf.core.err.permission_denied.v1~",
  "title": "Permission Denied",
  "status": 403,
  "detail": "You do not have permission to perform this operation",
  "instance": "/v1/consumer-groups/{group_id}",
  "trace_id": "<request-trace-id>",
  "context": {
    "reason": "access denied by policy",
    "resource_type": "gts.cf.core.events.request.v1~"
  }
}
```

The group is not removed: principal A's `GET /v1/consumer-groups/{group_id}` still answers `200`.

### 3. LIST excludes tenant A's group

```
GET /v1/consumer-groups
Authorization: Bearer <tenant-b-token>

→ 200 OK  { "items": [ ... ] }   # tenant A's groups absent
```

### 4. JOIN returns 403 ConsumerGroupNotOwned

```
POST /v1/subscriptions
Authorization: Bearer <tenant-b-token>
{ "consumer_group": "{group_id}", ... }

→ 403 Permission Denied (ConsumerGroupNotOwned)
```

```json
{
  "type": "gts://gts.cf.core.errors.err.v1~cf.core.err.permission_denied.v1~",
  "title": "Permission Denied",
  "status": 403,
  "detail": "You do not have permission to perform this operation",
  "instance": "/v1/subscriptions",
  "trace_id": "<request-trace-id>",
  "context": {
    "reason": "consumer group '{group_id}' was created by another principal",
    "resource_type": "gts.cf.core.events.consumer_group.v1~"
  }
}
```

No subscription is created, and tenant A's members of `{group_id}` are untouched.
