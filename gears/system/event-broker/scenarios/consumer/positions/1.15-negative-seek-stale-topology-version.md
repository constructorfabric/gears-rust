# SEEK rejects a stale topology version

A SEEK whose `topology_version` differs from the subscription's current `topology_version` is rejected `412 TopologyVersionMismatch`. A concurrent JOIN by another group member rebalances the group and bumps `topology_version`, so a member that seeks with the version it observed before the rebalance is told its view is stale - distinctly from naming a partition it never owned. The fence is wholesale (checked before any per-partition assignment check) and atomic (no cursor is seeded), and it is checked even for a partition the member still owns. The response body is minimal: it carries no `topology_version` and no assignment - the client re-reads the subscription, the single source of truth for the fresh state, and re-seeks.

## Setup

- Run [Cold JOIN against a fresh group](../subscriptions/1.01-positive-cold-join-fresh-group.md) so `{sub_id}` is created with `topology_version` `1`.
- A second member JOINs the same group, rebalancing it and bumping `topology_version` to `2`. `{sub_id}` keeps `("acme.orders.v1", 0)` in its assignment.

## Request

The member echoes the now-stale `topology_version` `1` it observed at JOIN, for a partition it still owns.

```http
POST /v1/subscriptions/{sub_id}:seek HTTP/1.1
Host: broker.example.com
Authorization: Bearer <tenant-token>
Content-Type: application/json

{
  "topology_version": 1,
  "partition_positions": {
    "gts.cf.core.events.topic.v1~acme.orders.v1:0": "earliest"
  }
}
```

## Expected response

- `412 Precondition Failed` (`PD`)
- Minimal body: no `topology_version`, no assignment. The `topology_version_mismatch` violation names the subscription resource only.

```json
{
  "type": "gts://gts.cf.core.errors.err.v1~cf.core.err.failed_precondition.v1~",
  "title": "Failed Precondition",
  "status": 412,
  "detail": "Operation precondition not met",
  "instance": "/v1/subscriptions/{sub_id}:seek",
  "trace_id": "<request-trace-id>",
  "context": {
    "resource_type": "gts.cf.core.events.subscription.v1~",
    "violations": [
      {
        "type": "topology_version_mismatch",
        "subject": "{sub_id}",
        "description": "subscription topology changed; re-read the subscription and re-seek"
      }
    ]
  }
}
```

## Recovery

- The client re-reads its subscription: `GET /v1/subscriptions/{sub_id}` returns the current `topology_version` (`2`) and `assigned` set. This is the single source of truth for the fresh state; the error body carries none of it.
- The client re-seeks with `topology_version` `2` for its current partitions, which succeeds.

## Side effects

- Nothing is applied - the fence precedes every cursor write, so partition `0` is not seeded despite being owned. The client's session cursor state is unchanged until the re-seek at the current version.
