# SEEK succeeds after a join-triggered rebalance, once the client re-reads

When a second member JOINs a consumer group, the group rebalances: the first member's assignment shrinks to a subset and the group's `topology_version` is bumped. A SEEK the first member issues with the version it observed before the rebalance is fenced off with `412 TopologyVersionMismatch` (the wholesale, atomic fence of [1.15](./1.15-negative-seek-stale-topology-version.md)). The recovery is deterministic: the member re-reads its subscription for the current `topology_version` and its shrunk assignment, then re-seeks a partition it still owns at that version, which succeeds. This scenario asserts the whole flow through to the successful re-seek, with the topology bump caused by a JOIN.

## Setup

- Register `acme.orders.v1` with 4 partitions.
- Member A [cold-JOINs a fresh group](../subscriptions/1.01-positive-cold-join-fresh-group.md) as `{sub_a}`: it is the only member, so it is assigned all 4 partitions at `topology_version` `1`.
- Member B JOINs the same group as `{sub_b}`: the rebalance bumps `topology_version` to `2` and shrinks `{sub_a}`'s assignment to 2 of the 4 partitions. A still owns `("acme.orders.v1", {p_kept})`.

## Request 1 - SEEK at the stale pre-join version

A echoes the `topology_version` `1` it observed at JOIN, for a partition it still owns.

```http
POST /v1/subscriptions/{sub_a}:seek HTTP/1.1
Content-Type: application/json

{ "topology_version": 1,
  "partition_positions": [{ "topic": "gts.cf.core.events.topic.v1~acme.orders.v1", "partition": {p_kept}, "value": "earliest" }] }

→ 412 Precondition Failed  (topology_version_mismatch; minimal body - no topology_version, no assignment)
```

Nothing is applied: the fence precedes every cursor write, so `{p_kept}` is not seeded.

## Recovery - re-read, then re-seek at the current version

```http
GET /v1/subscriptions/{sub_a} HTTP/1.1

→ 200  { ..., "topology_version": 2, "assigned": [ ..2 partitions.. ] }
```

```http
POST /v1/subscriptions/{sub_a}:seek HTTP/1.1
Content-Type: application/json

{ "topology_version": 2,
  "partition_positions": [{ "topic": "gts.cf.core.events.topic.v1~acme.orders.v1", "partition": {p_kept}, "value": "earliest" }] }

→ 200  [{ "topic": "gts.cf.core.events.topic.v1~acme.orders.v1", "partition": {p_kept}, "value": 0 }]
```

## Side effects

- The first SEEK seeds no cursor (fenced).
- The re-seek at `topology_version` `2` resolves `earliest` to the partition's floor cursor and seeds the group cursor for `{p_kept}`.
