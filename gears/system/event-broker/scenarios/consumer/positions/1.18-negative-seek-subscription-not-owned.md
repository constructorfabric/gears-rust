# SEEK by a principal that did not JOIN the subscription → 403 SubscriptionNotOwned

A subscription belongs to the principal that JOINed it: the subject, its tenant and its subject type, as the JOIN's credentials carried them (token scopes are not part of it). Only that principal may SEEK it, since SEEK moves the group's cursors. Another principal, even one of the same tenant, is refused with `403 Permission Denied` (`SubscriptionNotOwned`) right after the tenant check: before the open-stream check, so the refusal is the same whether or not a stream is open, and with no policy call beyond the tenant check.

## Setup

- The deployment authenticates with static tokens. `<principal-a-token>` and `<principal-b-token>` are bound to two subjects of the same tenant `{tenant_id}`.
- Principal A creates a group `{group_id}` (`POST /v1/consumer-groups`) and JOINs it with one interest on `gts.cf.core.events.topic.v1~acme.orders.v1` for `{tenant_id}` → `{sub_id}`, assigned partition `0`. Nothing has SEEKed it yet.

## Request (principal B)

```http
POST /v1/subscriptions/{sub_id}:seek HTTP/1.1
Host: broker.example.com
Authorization: Bearer <principal-b-token>
Content-Type: application/json

{
  "topology_version": 1,
  "positions": {
    "gts.cf.core.events.topic.v1~acme.orders.v1": [
      { "partition": 0, "value": "earliest" }
    ]
  }
}
```

## Expected response

- `403 Permission Denied` (`SubscriptionNotOwned`)

```json
{
  "type": "gts://gts.cf.core.errors.err.v1~cf.core.err.permission_denied.v1~",
  "title": "Permission Denied",
  "status": 403,
  "detail": "You do not have permission to perform this operation",
  "instance": "/v1/subscriptions/{sub_id}:seek",
  "trace_id": "<request-trace-id>",
  "context": {
    "reason": "subscription '{sub_id}' was joined by another principal",
    "resource_type": "gts.cf.core.events.subscription.v1~"
  }
}
```

## Side effects

- No cursor is written: principal A's `GET /v1/events:stream?subscription={sub_id}` then answers `409` `PositionsNotSet` for partition `0`.
